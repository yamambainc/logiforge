# HTML の書き方

共通の原則は [docs-writing](../docs-writing/SKILL.md) に従う。ここには HTML に固有の規則だけを書く。

## 役割

- HTML は、正本の md への入口にとどめる。載せるのは、概要と図。
  - 仕様の詳細を写さない。仕様の節へは、md へのリンクで飛ばす。
  - なぜ：メンテコスト。docs-writing の「正本は 1 か所に置き、ほかはリンクで指す」を HTML に当てはめたもの。
- 長い一覧は、折りたたんで載せない。md の一覧へリンクする。
  - なぜ：メンテコスト。折りたたんでも写しは写しで、元が変わるたびに直すことになる。
  - なぜ：認知負荷。折りたたんだ中身は、印刷で消えることがある。

## 構成

- 1 ページで 1 つの話題を扱う。
  - なぜ：認知負荷。docs-writing の「節は『何についてか』で切る」と同じ考え。
- 1 画面目で全体がつかめるようにする。目的と概念図を、最初の画面に置く。
  - なぜ：認知負荷。docs-writing の「冒頭の数行に想定用途を書く」を HTML に当てはめたもの。

## 図と依存

- 図はインラインの SVG にする。
  - なぜ：外部依存なしで描画できるようにするため。
- 外部 CDN（スクリプト・スタイル・フォント）を使わない。
  - なぜ：メンテコスト。置き場所が変わったり、オフラインで開いたりしても壊れないようにするため。
- ほかのページへのリンクは、相対パスで書く。
  - なぜ：メンテコスト。公開先が変わっても、リンクを直さずに済む。

## 読める環境

- 狭い画面と印刷でも読めるようにする。
  - 横に長い図は、横にスクロールできる箱に入れる。
  - 印刷で消える要素（折りたたみなど）に、中身を置かない。
  - なぜ：認知負荷。開く環境によって読めない部分ができる。

## チェックリスト

書き終えたら、変えたファイルについて確かめる。

- [ ] 外部の URL を読み込んでいない（`grep -nE '(src|href)="https?://'` が空）。
- [ ] リンク切れが無い（相対リンクの先のファイルがある）。
- [ ] 仕様を写していない（`grep -nE '<table|<details'` が空。md の決まりの文を写していない）。
- [ ] 1 画面目に、目的と概念図がある。
- [ ] 狭い画面（幅 360px 程度）と印刷プレビューで読める。
- [ ] docs-writing-md のチェックリストにある grep（経緯・状態の語、連番の ID、不自然な語）を HTML にも実行し、何も残っていない。
