# HTML の書き方

共通の原則は [docs-writing](../docs-writing/SKILL.md) に従う。ここには HTML に固有の規則だけを書く。

## 役割

- HTML は、正本の md への入口にとどめる。載せるのは、概要と、HTML が正本になる概念図だけ。
  - 仕様の詳細を写さない。仕様の節へは、md へのリンクで飛ばす。
  - なぜ：メンテコスト。docs-writing の「正本は 1 か所に置き、ほかはリンクで指す」を HTML に当てはめたもの。
- 長い一覧は、折りたたんで載せない。md の一覧へリンクする。
  - なぜ：メンテコスト。折りたたんでも写しは写しで、元が変わるたびに直すことになる。

## 構成

- 1 ページで 1 つの話題を扱う。
  - なぜ：認知負荷。docs-writing の「節は『何についてか』で切る」と同じ考え。
- 1 画面目で全体がつかめるようにする。目的と概念図を、最初の画面に置く。
  - なぜ：認知負荷。docs-writing の「冒頭の数行に想定用途を書く」を HTML に当てはめたもの。

## 図

- HTML に描いてよい図は、HTML が正本になる概念図だけにする。
- md にある図を、HTML に描き直さない。
  - なぜ：メンテコスト。描き直した図は写しになる。
- 図の中の文字は、[docs-writing](../docs-writing/SKILL.md) の「図」に従う。
- 図はインラインの SVG にする。
  - なぜ：下の「外部の CDN を使わない」から導ける。描画のライブラリ（mermaid など）を読み込まずに描けるのは、インラインの SVG だから。

## 外部への依存とリンク

- 外部の CDN（スクリプト・スタイル・フォント）を読み込まない。
  - なぜ：メンテコスト。置き場所が変わったり、オフラインで開いたりしても壊れないようにするため。
- md へのリンクは、md が描画される場所（GitHub など）の URL を指す。
  - なぜ：認知負荷。手元で HTML を開いても、md を描画された状態で読めるようにするため。
- 資産（画像など）へのリンクは、相対パスにする。
  - なぜ：メンテコスト。HTML と一緒に置き場所を移しても、リンクを直さずに済む。

## HTML 独自の規則

共通の原則から導いたものではなく、HTML という形式のために置く規則。

- 狭い画面と印刷でも読めるようにする。
  - 横に長い図は、横にスクロールできる箱に入れる。
  - 印刷で消える要素（折りたたみなど）に、中身を置かない。

## チェックリスト

書き終えたら、変えたファイルについて確かめる。[docs-writing](../docs-writing/SKILL.md) の共通のチェックリストも実行する。

- [ ] 外部の資産を読み込んでいない（`grep -nE '<(script|img|iframe)[^>]+src="https?://|<link[^>]+href="https?://'` が空）。`<a href>` は対象外。
- [ ] 仕様を写していない（`grep -nE '<table|<details'` が空。md の決まりの文を写していない）。
- [ ] md にある図を描き直していない。
- [ ] 1 画面目に、目的と概念図がある。
- [ ] 狭い画面（幅 360px 程度）と印刷プレビューで読める。
