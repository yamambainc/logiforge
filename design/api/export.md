# 書き出しの形

木を書き出す API（`exportTree`）の、JSON と Markdown の形を確かめるときに読む。
要件は、[エクスポート](../../docs/architecture/README.md) が正本である。

## 共通

- あるリビジョン（`main` のコミット）の木を書き出す。リビジョンを指定しなければ、今の `main` を書き出す。
- ノードは、根から深さ優先の順に並べる。仮説の子ストーリーと、ストーリーの子仮説は、ファイルの配置の順（識別子の順）にする。
- 検証結果は、差し替えられたものも含める。
- open の apply request と人への依頼は含めない。
  - なぜ：書き出しは、ある時点の木と根拠を、Logiforge の外で読むためのものだから。やりとりは、GitForge にある。

## JSON

| 項目 | 内容 |
|---|---|
| `format` | 形の名前と版。`logiforge.export.v1`。形を変えるときは、版を上げる |
| `repository` | repository の名前 |
| `revision` | 書き出したリビジョン |
| `root_hypothesis_id` | 根の仮説 |
| `nodes` | ノード。形は、API の `Hypothesis` と `Story` と同じ（open の apply request と人への依頼は、空の一覧） |
| `verdicts` | 検証結果。各項目は、識別子、仮説、値、有効か（`valid`）、差し替えたもの、レポートの本文、artifact、引用を持つ |

- artifact の中身は含めない。file の artifact は、sha256 を書く。中身は、`getArtifact` で読む。

## Markdown

- 1 つ目の見出しは、repository の名前である。その下に、リビジョンと根の仮説を書く。
- ノードごとに、2 つ目の見出しを 1 つ置く。
  - 仮説：`## 仮説 <識別子>`。主文、親、値、葉・要再検討・inactive を書く。背景情報と検証結果は、3 つ目の見出しにする。
  - ストーリー：`## ストーリー <識別子>：<タイトル>`。概要、親、値、inactive にした理由を書く。
- 親子関係は、見出しの深さではなく、「親：」の行で表す。
  - なぜ：木は 24 段まであり、Markdown の見出しの深さ（6 段）に収まらないから。
- 主文、概要、背景情報、レポートの本文は、引用（`>`）にする。
  - なぜ：本文の中の見出しが、書き出しの見出しの構造を崩さないようにするため。
