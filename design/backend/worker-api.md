# worker の内部 API

バックエンドが、git に書くときに worker を呼ぶ口を、実装するときに読む。
この API は、バックエンドの [木の書き込み](ports/tree-write.md) のポートの、アダプタが使う。クライアントには公開しない。

## 操作

| 操作 | 受け取るもの | 返すもの |
|---|---|---|
| 用意する | repository の名前 | 書き込めるか |
| 書く | repository の名前、親のリビジョン、ファイルの変化、trailer、コミットの時刻、書く ref と期待する値 | 新しいリビジョンと、書いたあとの `latest` |

- 「書く」は、ポートの「リビジョンを作る」と「ref を書く」を、1 回の要求にまとめたものである。
  - なぜ：作ったコミットを、要求をまたいで worker に置いておかずに済むから。
  - ref だけを書く（close で `head` を消す）ときは、親とファイルの変化を渡さない。
- ファイルの変化は、パスと中身の組である。
  - 中身の代わりに、git の blob の SHA を渡してもよい。反映と、回答のファイルを版に加えるときは、artifact の中身を送り直さず、スナップショットにある blob の SHA を渡す（[スナップショット](snapshot.md) の `artifacts`）。
- 期待する値と違って書けなかったときは、どの ref が違ったかを返す（[失敗の種類](ports/tree-write.md)）。

## 認証

- バックエンドと worker は、同じ秘密の鍵を設定に持つ（[設定と秘密情報](../adapters/README.md)）。
- バックエンドは、要求に、その鍵を Bearer トークンとして付ける。worker は、鍵が合わない要求を拒む。
- worker の内部 API は、バックエンドからだけ届くネットワークに置く。

## 送り直し

内部 API の「書く」は、同じ要求を送り直しても、結果が同じになる。

- コミットの中身は、受け取ったものだけで決まる。コミットの時刻も、バックエンドが決めて渡す。
  - そのため、同じ要求からは、同じ SHA のコミットができる。
- 送り直しで、ref がすでに、その SHA を指していれば、書けたものとして応答する。
  - なぜ：前の要求が push のあとに切れたとき、送り直しを lease の失敗と取り違えないため。
- worker は、送り直しを見分けるための記録を持たない。git の ref の今の値だけで決める。
