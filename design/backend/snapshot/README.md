# スナップショット

バックエンドが読むスナップショットツリーと、コミットの記録の形を確かめるときに読む。
作るのは [worker](../worker/README.md) だけで、バックエンドは読むだけである。

## 読む順

1. このページ：考え方、中身、読み方
2. [main のスナップショット](main.md)：すべてのコミットに作ること、コミットの記録から引くもの、ノードを変えたコミット、`latest`
3. [ブランチのスナップショット](branch.md)：ブランチの差分、ブランチのコミットの木、向き先に重ねること、ブランチの履歴

## 考え方

- スナップショットは、あるコミットの木を解析したものである。読むためだけにある。
  - 正本は、git の `main` である（[木のファイル配置](../../files/README.md)）。
  - スナップショットは、git からいつでも作り直せる。
- スナップショットを作って置き場に書くのは、worker だけである。
  - バックエンドは、木を読むのも、反映の検査も、スナップショットの上で行う。git を読むのは、apply request の作成の検査のときだけである（[作成](../apply-request/create.md#作成)）。
  - なぜ：永続する clone を持つものを worker の 1 つにし、バックエンドがデータを保持しないようにするため（[worker](../worker/README.md)）。
- コミットの SHA ごとに 1 つ作る。中身は変えない。上書きも削除もしない。
  - なぜ：SHA で引けば、いつ読んでも同じ中身なので、キャッシュを置くときに、そのままキャッシュできるから。
  - 例外は、`latest`、`main` の並びの索引、ブランチの履歴とその一覧である（[スナップショットの置き場](../ports/snapshot-store.md)）。

## 中身

- 形の正本は、`internal/snapshot` の Go の型である。このページには、項目の表だけを置く。
- 形にはフォーマットバージョン（`format_version`）を持たせる。項目を足すときも、フォーマットバージョンを上げる。読むときにフォーマットバージョンを確かめる。
- 今のフォーマットバージョンは 6 である。

`main` のコミットのスナップショットは、コミットの記録と、スナップショットツリーの 2 つに分けて置く。

- どちらも、`main` のすべてのコミットに置く（[すべてのコミットに作る](main.md#すべてのコミットに作る)）。
- ブランチの先頭のコミットには、コミットの記録と差分を置く（[ブランチのスナップショット](branch.md#ブランチのスナップショット)）。

### コミットの記録

コミットの記録は、数 KB である。

| 項目 | 内容 |
|---|---|
| `revision` | コミットの SHA。API の `commit` に当たる |
| `parent` | first-parent のコミットの SHA。最初のコミットでは null。`branch` では、base（`main` と分かれた点） |
| `number` | `main` のコミットだけ。最初のコミットを 1 とする、first-parent の番号 |
| `kind` | `main`（`main` のコミット）、`branch`（利用者が push したブランチの先頭） |
| `committed_at` | コミットの時刻 |
| `trailers` | コミットの trailer（[記録の形式](../../files/revisions.md)） |
| `warnings` | `main` のコミットだけ。下に書く |
| `changes` | `main` のコミットだけ。下に書く |
| `paths` | `branch` のコミットだけ。base から変わったファイルのパスと、変わり方（`added`、`modified`、`deleted`） |

- `warnings` は、次のものを持つ。
  - 反映によらないこと（[反映かの判定](../verify/README.md)）
  - このコミットで新しく破れた不変条件
  - worker が見つけた警告（重なり、`main` の書き換え）（[すること](../worker/patrol.md#すること)）
- `changes` は、このコミットで変わったノードごとに、次のものを持つ（[ノードを変えたコミット](main.md#ノードを変えたコミット)）。
  - ノードの識別子
  - 変わったファイルの種類（`hypothesis`、`background`、`verdict`、`story`、`inactivated`）とパス
  - そのノードを前に変えたコミット（`previous`。番号と SHA。初めてなら null）

### スナップショットツリー

| 項目 | 内容 |
|---|---|
| `nodes` | ノードごとの、ファイルと値。下に書く |
| `artifacts` | `artifacts/sha256/` にあるファイルの一覧。各項目は、sha256、blob の SHA、大きさを持つ。中身は持たない |
| `other` | どのノードにも artifact にも当たらないファイル（木の外のファイルなど）。元のファイルの一覧を、そのまま戻すために持つ |
| `warned` | 最初のコミットからこのコミットまでのうち、警告のある `main` のコミットの一覧。各項目は、番号、SHA、警告の種類を持つ |
| `broken` | このスナップショットツリーで破れている不変条件のすべて（前のコミットから破れているものを含む） |

- `nodes` の各ノードは、次のものを持つ。
  - ファイルの中身（git のファイルのバイトそのもの）と、blob の SHA
  - 計算した値・葉・要再検討・inactive
  - そのノードを最後に変えたコミット（`last_changed`。番号と SHA）（[ノードを変えたコミット](main.md#ノードを変えたコミット)）
  - ストーリーだけ：`inactivated.md` が加わったコミットの番号（`inactivated_at`。inactive でなければなし）
  - 検証結果のファイルだけ：そのファイルが加わったコミット（`added`。番号、SHA、反映の apply request）
- ノードのファイルを持つのは、バックエンドが、スナップショットから元のファイルの一覧に戻し、[差分の検査](../checks.md) に渡すためである。
- スナップショットツリーは、`main` のコミットの一覧（history）を持たない。ノードごとの、変えたコミットの一覧も持たない。
  - なぜ：どちらも、コミットの数とともに伸びるから。すべてのコミットにスナップショットツリーを作るので、持つと、置き場の容量がコミットの数の 2 乗で増える（[スナップショットの時間と大きさ](../../estimates/snapshot.md#スナップショットの大きさ)）。
  - かわりに、コミットの記録と、`main` の並びの索引から引く（[コミットの記録から引くもの](main.md#コミットの記録から引くもの)）。
  - `warned` は、警告のあるコミットだけを持つ。警告の数でしか伸びない。
  - `warned` の数に上限は置かない。なぜ：警告のあるコミットが増え続けるのは、`main` の保護が外れて、反映によらない push が続くときである。それは異常で、警告そのもので気づくから。
- スナップショットツリーは、すべてのノードを持ち、根の子の部分木ごとには分けない。数百 KB から数 MB で、圧縮して置く。
- 値は、作るときに計算して入れる（[真偽値の伝播](../../../docs/tree/propagation.md)）。
  - なぜ：読むたびに計算しないため。スナップショットは正本ではないので、値を持ってもファイルと食い違わない。
- artifact の中身は、スナップショットとは別に、sha256 の名前で置き場に置く。
- 形を変えるときは、置き場の接頭辞ごと新しくして作り直す。古いものは消さない。
  - ブランチのスナップショットは、作り直せないので、古い形のまま読むか、移す。

## 読む

- バックエンドは、木を読むとき、`latest` を読み、次にその `main` の SHA のスナップショットツリーを読む。
  - API で `commit` を指定されたら、その SHA のスナップショットツリーを読む。
  - その SHA のスナップショットツリーがなければ、`snapshot_pending` を返す（[書いた直後の読み](../../api/writes.md)）。まだ取り込まれていないのか、git にもない SHA なのかは、区別しない。バックエンドは git を読まないからである。
- apply request の先頭のコミットの一覧は、[ブランチの履歴](branch.md#ブランチの履歴) から読む。
- バックエンドは、読んだものを保持しない。読むたびに置き場から取る（[状態を持たない](../README.md#状態を持たない)）。
  - 置き場は、バックエンドから転送の費用なしで読める場所に置く（[スナップショットの置き場のアダプタ](../../adapters/snapshot-store.md)）。
