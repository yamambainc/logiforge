# バックエンド

バックエンド（core）が、どのルールを持ち、何を計算するかを確かめるときに読む。
ルールを持つのはこのレイヤーだけ、という決まりは [レイヤー構成](../architecture.md) が正本である。

## 持つルール

| ルール | 要件 | 実現 |
|---|---|---|
| 不変条件 | [仮説とストーリーの木](../../docs/tree/README.md)、[inactive 化](../../docs/tree/inactive.md) | [差分の検査](checks.md) |
| 反映の条件 | [論理レビュー](../../docs/apply-request/review.md) | [反映の手順](merge.md) |
| 対象ノードの変化 | [反映](../../docs/apply-request/README.md) | [反映の手順](merge.md) |
| 値の計算 | [真偽値の伝播](../../docs/tree/propagation.md) | 下の「計算」 |
| 着手できる作業 | [着手できる作業とイベント](../../docs/work/README.md) | 下の「計算」 |
| 作業の終わりの判定 | [作業の終わりの判定](../../docs/work/README.md) | 下の「計算」 |
| 認可 | [役割](../../docs/roles/README.md) | 下の「認可」 |

バックエンドが使うポートは、[ポート](ports/README.md) に書く。

## 認可

- 主体には、次の 2 種類がある。
  - `user`：WebUI を使う利用者
  - `client`：CLI を使う主体（エージェントか人）
- `user` が使える書き込みは、利用者の 2 つの操作だけである。
  - repository の作成（根の主文を含む）
  - 人への依頼への回答
    - 回答に添えるファイルの blob と artifact の登録
- それ以外の書き込みは、`client` だけが使える。
- 主体とトークンは、[状態ストア](ports/state-store.md) に置く。

## 操作と差分

- API が受け取る 4 種類の操作（[操作](../../docs/apply-request/README.md)）を、バックエンドがファイルの変化に変える。
  - `story.create`：仮説とストーリーのディレクトリを加える。
  - `story.inactivate`：`inactivated.md` を加える。
  - `verdict.submit`：`verdicts/` に検証結果のファイルを加える。
  - `node.edit`：`background.md` の末尾に文章を加える。
- 操作とファイルの変化は 1 対 1 なので、バックエンドは差分から操作を復元できる。
  - なぜ：操作を別に保存しなくても、差分だけで API の応答を作れるようにするため。
  - 差分の起点は、[反映の手順](merge.md) の base である。
- 版は、バックエンドが [木のリポジトリ](ports/tree-repository.md) の「リビジョンを作る」で作る。
  - 版には、差分を書いたセッションと署名を記録する（[記録の形式](../files/revisions.md)）。

## 計算

バックエンドは、次のものを保存せず、木のリポジトリとやりとりのデータから計算する。

- 値と、葉・要再検討・inactive
  - 「木を読む」で読んだ `tree/` のファイルだけから計算する。
- 引用元の変化
  - 有効な検証結果の部分木の引用ごとに、「変更を列挙する」で、引用したリビジョンから今の `main` までの、部分木のパスの変化を探す。
- 着手できる作業
  - 木の作業は、`tree/` から計算する。
  - apply request と人への依頼の作業は、[やりとり](ports/interaction.md) の提案、版、レビュー、人への依頼から計算する。
- 作業の終わりの判定
  - 根拠部分木を `tree/` から求め、上の着手できる作業のうち、根拠部分木にあるものを数える。

## イベントと突き合わせ

- バックエンドは、やりとりからのイベントと自分の反映を、[状態ストア](ports/state-store.md) のイベントのログに記録する。
- バックエンドは、定期的に突き合わせを行う。
  - `main` の今のリビジョンが、状態ストアの「最後に反映したリビジョン」と同じかを確かめる。
  - 違えば、反映の手順によらない変更として、API の応答とイベントで警告する。
