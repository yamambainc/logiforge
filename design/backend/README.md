# バックエンド

バックエンド（core）が、どのルールを持ち、何を計算するかを確かめるときに読む。
ルールを持つのは、このレイヤーだけである（[レイヤー構成](../architecture.md)）。

## 持つルール

| ルール | 要件 | 実現 |
|---|---|---|
| 不変条件 | [仮説とストーリーの木](../../docs/tree/README.md)、[inactive 化](../../docs/tree/inactive.md) | [差分の検査](checks.md) |
| 反映の条件 | [論理レビュー](../../docs/apply-request/review.md) | [反映の手順](merge.md) |
| 対象ノードの変化 | [反映](../../docs/apply-request/README.md) | [反映の手順](merge.md) |
| 値の計算 | [真偽値の伝播](../../docs/tree/propagation.md) | 下の「計算」 |
| 着手できる作業 | [着手できる作業と通知](../../docs/work/README.md) | 下の「計算」 |
| 作業の終わりの判定 | [作業の終わりの判定](../../docs/work/README.md) | 下の「計算」 |

## 操作と差分

- API が受け取る 4 種類の操作（[操作](../../docs/apply-request/README.md)）を、バックエンドがファイルの変化に変える。
  - `story.create`：仮説とストーリーのディレクトリを加える。
  - `story.inactivate`：`inactivated.md` を加える。
  - `verdict.submit`：`verdicts/` に検証結果のファイルを加える。
  - `node.edit`：`background.md` の末尾に文章を加える。
- 操作とファイルの変化は 1 対 1 なので、バックエンドは差分から操作を復元できる。
  - なぜ：操作を別に保存しなくても、プロバイダの差分だけで、API の応答を作れるようにするため。
- 変化は、ブランチへのコミットとして、プロバイダに置く。

## セッション ID の記録

- バックエンドは、版ごとに、差分を書いたセッションを記録する。
  - コミットの trailer に `Logiforge-Session-Id:` として書く。
  - なぜ：どのプロバイダでも、git の中に同じ形で残るから。
- レビューのセッションと、使ったプロンプトのリビジョンは、プロバイダのレビューに記録する（[プロバイダ](../providers/README.md)）。

## 計算

バックエンドは、次のものを保存せず、`main`（またはリビジョンを指定したコミット）のファイルと、プロバイダのデータから計算する。

- 値と、葉・要再検討・inactive
  - `tree/` のファイルだけから計算する。
- 引用元の変化
  - 有効な検証結果の部分木の引用ごとに、`git log <引用した commit>..main -- <部分木のパス>` で、検証結果の差し替えとストーリーの inactive 化を探す。
- 着手できる作業
  - 木の作業は、`tree/` から計算する。
  - apply request と人への依頼の作業は、プロバイダの提案、版、レビュー、人への依頼から計算する。
- 作業の終わりの判定
  - 根拠部分木を `tree/` から求め、上の着手できる作業のうち、根拠部分木にあるものを数える。

## イベント

- バックエンドは、プロバイダからイベントを受け取り、API の [webhook](../api/webhook.md) として送る。
- `main` に、バックエンドの反映によらないコミットができたら、それを検出して警告する（[GitHub アダプタ](../providers/github.md)）。
