# 認証

バックエンドが、API の要求を送った主体を確かめるときに使うポートを確かめるために読む。

## 操作

| 操作 | 内容 |
|---|---|
| 主体を確かめる | トークンを受け取り、主体と、主体の種類（`user` か `client`）を返す |
| repository を読めるか確かめる | 主体が、その repository を読めるかを返す |

- どの操作を使えるかの判定（認可）は、このポートではなくバックエンドが行う（[認可](../README.md)）。
- 構成ごとの実装は、[アダプタ](../../adapters/README.md) に書く。

## ポートにした理由

- 主体の正本が、構成によって違うから（[このレイヤー構造にした理由](../../architecture.md)）。
- ほかのポートと同じく、起動処理が構成に合ったアダプタを差し込むだけで済むから（[起動時の組み立て](../../architecture.md)）。
