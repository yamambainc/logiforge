# 木の読み書き

バックエンドが、木のファイルを読み書きするときに使うポートを確かめるために読む。
ファイルの形式（このポートの契約）は、[木のファイル配置](../../files/README.md) が正本である。

## 操作

| 操作 | 内容 |
|---|---|
| 用意する | repository の git リポジトリに書き込めることを確かめる。すでに済んでいれば、何もしない |
| 今の main を読む | `main` が指すリビジョンを返す。`main` がなければ、ないことを返す |
| 最初のリビジョンで main を作る | 親を持たないリビジョンを作り、`main` をそこに置く |
| 木を読む | あるリビジョンの、指定したパスの下のファイルを読む |
| リビジョンの情報を読む | あるリビジョンの、親、tree、メッセージ、時刻を返す |
| 変更を列挙する | 2 つのリビジョンの間で、指定したパスを変えたリビジョンを列挙する |
| 共通の祖先を求める | 2 つのリビジョンの共通の祖先（base）を求める |
| リビジョンの並びを読む | `main` が通ってきたリビジョンを、古い順に読む |
| リビジョンを作る | ある親のリビジョンに、ファイルの変化を足した新しいリビジョンを作る。名前を指定すれば、その名前で置く。`main` は動かさない |
| 名前でリビジョンを読む | 名前を付けて置いたリビジョンを返す |
| main を進める | `main` を、期待する親のリビジョンから、指定したリビジョンへ進める |

- リビジョンは、ポートの外からは不透明な文字列として扱う。
- 「リビジョンの情報を読む」は、署名の確認（[記録の形式](../../files/revisions.md)）と、ノードの履歴に使う。

## 失敗の種類

次の失敗は、ほかの失敗と区別できる形で返す。

| 操作 | 失敗 | バックエンドの扱い |
|---|---|---|
| 最初のリビジョンで main を作る | `main` がすでにある | 用意の続きの判定に進む（[repository の用意](../README.md)） |
| リビジョンを作る | 同じ名前のリビジョンがすでにある | 版の番号を進めて作り直す |
| main を進める | `main` が期待する親でない | 反映しない（[反映の手順](../merge.md)） |

- なぜ：どれも、同時に走った別の処理に負けたときに起きる。バックエンドが、失敗の種類で次の動きを決めるため。

## 名前

- バックエンドは、名前を構造で渡す。
  - 版：apply request の識別子と、版の番号
  - 回答：人への依頼の識別子
  - 反映のリビジョンには、名前を付けない。「main を進める」で `main` に置く。
- 名前から git の ref のパスを組み立てるのは、アダプタである（[名前を付けたリビジョン](../../adapters/git.md)）。
  - なぜ：ref の置き方を、バックエンドに漏らさないため。

## 決まり

- `main` を作るのは、repository の用意（[バックエンド](../README.md) の「repository の用意」）だけである。
- `main` を進めるのは、[反映の手順](../merge.md) だけである。
- 用意を途中から続けるときの判定は、バックエンドが行う（[repository の用意](../README.md)）。
  - なぜ：判定に署名の確認が要り、署名の鍵はバックエンドだけが使うから。
