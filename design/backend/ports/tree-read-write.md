# 木の読み書き

バックエンドが、木のファイルを読み書きするときに使うポートを確かめるために読む。
ファイルの形式（このポートの契約）は、[木のファイル配置](../../files/README.md) が正本である。

## 操作

| 操作 | 内容 |
|---|---|
| 用意する | repository の git リポジトリを、空の状態で作る。すでにあれば、何もしない |
| 列挙する | 用意済みの git リポジトリを、repository の名前と一緒に列挙する |
| 最初のリビジョンで main を作る | 親を持たないリビジョンを作り、`main` をそこに置く。`main` がすでにあれば、失敗する |
| 木を読む | あるリビジョンの木のファイルを読む |
| 変更を列挙する | 2 つのリビジョンの間で、指定したパスを変えたリビジョンを列挙する |
| 共通の祖先を求める | 2 つのリビジョンの共通の祖先（base）を求める |
| リビジョンの並びを読む | `main` が通ってきたリビジョンを、古い順に読む |
| リビジョンを作る | ある親のリビジョンに、ファイルの変化を足した新しいリビジョンを作り、名前を付けて置く。`main` は動かさない |
| 名前でリビジョンを読む | 名前を付けて置いたリビジョンを返す |
| main を進める | `main` を、期待する親のリビジョンから、指定したリビジョンへ進める |

- 「main を進める」は、`main` の今のリビジョンが期待する親と違えば、失敗する。
  - なぜ：検査したあとに `main` が動いていたら、その検査を無効にするため（[反映の手順](../merge.md)）。
- リビジョンは、ポートの外からは不透明な文字列として扱う。
- 名前は、版なら apply request の識別子と版の番号、回答なら人への依頼の識別子から求める（[artifact の置き方](../../files/artifacts.md)）。
- `main` を作るのは、repository の用意（[バックエンド](../README.md) の「repository の用意」）だけである。
- `main` を進めるのは、[反映の手順](../merge.md) だけである。
- repository の名前の正本は、アダプタが決める（[repository の登録](../../adapters/README.md)）。
- 用意を途中から続けるときの判定は、バックエンドが行う（[repository の用意](../README.md)）。
  - なぜ：判定に署名の確認が要り、署名の鍵はバックエンドだけが使うから。
