# スナップショットの置き場

バックエンドと worker が、[スナップショット](../snapshot.md) を置き、読むときに使うポートを確かめるために読む。

## 置くもの

| キー | 中身 | 書き方 |
|---|---|---|
| `<repository>/commits/<SHA>` | スナップショットのコミットの記録 | 1 度だけ書く。上書きも削除もしない |
| `<repository>/snapshots/<SHA>` | スナップショットの木 | 1 度だけ書く。上書きも削除もしない |
| `<repository>/artifacts/<sha256>` | artifact のファイルの中身 | 1 度だけ書く。上書きも削除もしない |
| `<repository>/latest` | 今の `main` の SHA と、force push の記録 | 条件付きで上書きする |

## 操作

| 操作 | 内容 |
|---|---|
| 読む | キーの中身を返す。なければ、ないことを返す |
| 1 度だけ書く | キーがなければ書く。あれば何もしない |
| `latest` を条件付きで書く | 今の `latest` が、期待した値のときだけ上書きする。違えば、違うことと今の値を返す |
| `latest` がある repository を列挙する | `latest` があるキーの、repository の名前を返す |

- SHA と sha256 のキーは、中身から決まる。そのため、同じキーに 2 つの書き手が書いても、中身は同じである。
- 「`latest` を条件付きで書く」は、比べることと書くことを、1 回の操作で行う。
  - なぜ：2 つのプロセスが同時に書いても、古い SHA に戻らないようにするため（[latest](../snapshot.md)）。

## 条件付きの書き込みを持たない置き場

比べることと書くことを 1 回で行えない置き場では、アダプタは次のように振る舞う。

- 書く前に今の値を読み、期待した値と同じときだけ書く。
- 書いたあとに読み直し、自分が書いた値か、その子孫の SHA でなければ、もう 1 度 [latest](../snapshot.md) の規則で書き直す。
- それでも、2 つの書き込みが重なると、`latest` が短い間だけ古い SHA を指すことがある。
  - 木は壊れない。正本は `main` で、`latest` は次の書き込みか worker で直る。
  - 書いたプロセスは、`latest` を読み直さず、自分が書いた SHA で応答を作る。そのため、書いた直後の応答は古くならない。

アダプタは、[スナップショットの置き場のアダプタ](../../adapters/snapshot-store.md) に書く。
