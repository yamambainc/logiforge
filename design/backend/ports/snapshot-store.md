# スナップショットの置き場

バックエンドが、[スナップショット](../snapshot.md) を読むときに使うポートを確かめるために読む。

## 置いてあるもの

| キー | 中身 | 変わるか |
|---|---|---|
| `v<フォーマットバージョン>/<repository>/commits/<SHA>` | `main` のコミットの記録。`main` のすべてのコミットにある | 変わらない |
| `v<フォーマットバージョン>/<repository>/snapshots/<SHA>` | `main` のスナップショットツリー。`main` のすべてのコミットにある（[すべてのコミットに作る](../snapshot.md#すべてのコミットに作る)） | 変わらない |
| `v<フォーマットバージョン>/<repository>/main/<番号>` | `main` の並びの索引。その番号の `main` のコミットの SHA（[コミットの記録から引くもの](../snapshot.md#コミットの記録から引くもの)） | `main` が書き換えられたときだけ変わる |
| `v<フォーマットバージョン>/<repository>/latest` | 取り込み終えたいちばん新しい `main` の SHA（[latest](../snapshot.md#latest)） | 変わる |
| `v<フォーマットバージョン>/repositories` | `latest` がある repository の名前の一覧 | 変わる |
| `keep/<repository>/artifacts/<sha256>` | artifact のファイルの中身 | 変わらない |
| `keep/<repository>/branches/<ブランチの名前>` | ブランチの履歴（[ブランチの履歴](../snapshot.md#ブランチの履歴)）。ブランチの名前は、パスとしてエスケープする（`/` を `%2F` に） | 変わる |
| `keep/<repository>/branch-snapshots/<SHA>` | ブランチの先頭のスナップショット（コミットの記録と差分を 1 つにまとめたもの）。中に自分のフォーマットバージョンを持つ | 変わらない |
| `keep/<repository>/branch-index` | 履歴のあるブランチの名前の一覧。消えたブランチを見つけるのに使う | 変わる |
| `keep/records/<GitForge の repository の識別子>/<pull request か issue の番号>` | worker が見た、署名の合う記録の控え。追記だけで、消さない（[記録の控え](../verify.md#記録の控え)）。識別子は、記録の署名に使うもの（Forgejo の id、GitHub の node_id）で、パスとしてエスケープする | 増える |
| `keep/records/<GitForge の repository の識別子>/cursor` | 記録の控えの、次に読む位置（コメントの `updated_at`） | 変わる |
| `keep/<repository>/broken` | 壊れていることの記録（[壊れた repository](../broken.md)）。壊れていなければ、空の記録 | 変わる |

- git から作り直せるものは、フォーマットバージョンの接頭辞（`v<フォーマットバージョン>/`）の下に置く。
  - フォーマットバージョン（`format_version`）が変わったら、新しいフォーマットバージョンの worker は、空の接頭辞から作り直す。古いフォーマットバージョンのものは、消さずに残す。
  - なぜ：形の違うスナップショットを、同じキーで混ぜないため。作り直せるので、移す必要がない。
- 作り直せないもの（ブランチの履歴と、その一覧と、ブランチのスナップショットと、壊れていることの記録と、記録の控え）と、形を持たないもの（artifact の中身）は、フォーマットバージョンの接頭辞の外の `keep/` に置く。
  - ブランチの履歴は、git から作り直せないので、バックアップを取る。形を変えるときは、読めるように移す。
  - ブランチのスナップショットも、消えたブランチの先頭のコミットは git から作り直せない。そのため、フォーマットバージョンの接頭辞の下に置かない。
    - 中に自分のフォーマットバージョン（`format_version`）を持たせ、読むときは、古いフォーマットバージョンのものも読む。
    - フォーマットバージョン 4 までは、`v4/` の下に置いていた。worker は、起動のあと repository ごとに 1 度、ブランチの履歴に出てくる先頭のうち、まだ `keep/` にないものを、`v4/` の下から移す。古いフォーマットバージョンの下のものは消さない。何度動かしても、結果は同じになる。
- 置き場の直下には、`v<フォーマットバージョン>/` と `keep/` だけを置く。なぜ：repository の名前（`v4` など）と、ぶつからないようにするため。
- `main` のコミットの記録があっても、スナップショットツリーがあるとは限らない。worker が、記録を置いたあと、スナップショットツリーを置く前に止まったときである。`latest` までのコミットには、どちらもある。
- ブランチの先頭のスナップショットは、コミットの記録と差分を 1 つのキーにまとめて置く。そのため、片方だけがあることはない。
- `latest` が指すコミットには、いつもスナップショットツリーがある。worker は、スナップショットツリーを置いてから `latest` を書く。
- `latest`、ブランチの履歴、ブランチの名前の一覧は、条件付きで書く（読んだときの値のときだけ書く）。静的ファイルストレージでは、ETag と `If-Match`（ないときは `If-None-Match: *`）で書く。
- ブランチの名前をエスケープするのは、`a` と `a/b` が、ファイルとディレクトリでぶつからないようにするため。

## 操作

| 種類 | 操作 | 内容 |
|---|---|---|
| 置き場を読む | 読む | キーの中身を返す。なければ、ないことを返す |

- このポートは、読むことだけを持つ。
- バックエンドは、置き場を読むだけである。
- 書くのは [worker](../worker.md) だけで、worker の中の別のインターフェースで書く。このポートには、書く操作を置かない。
  - なぜ：バックエンドが置き場に書かないことを、ポートの形で守るため。

アダプタは、[スナップショットの置き場のアダプタ](../../adapters/snapshot-store.md) に書く。
