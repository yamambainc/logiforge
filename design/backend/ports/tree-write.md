# 木の書き込み

バックエンドが、木の変更を git に書くときに使うポートを確かめるために読む。
ファイルの形式（このポートの契約）は、[木のファイル配置](../../files/README.md) が正本である。

## 操作

| 操作 | 内容 |
|---|---|
| 用意する | repository の git リポジトリに書き込めることを確かめる。すでに済んでいれば、何もしない |
| リビジョンを作る | 親のリビジョン（最初のリビジョンでは、なし）に、ファイルの変化を足した新しいリビジョンを作る。まだ ref には置かない |
| ref を書く | いくつかの ref を、それぞれ期待する今の値を付けて、1 回で書くか消す。どれか 1 つでも期待と違えば、どれも書かない |
| ブランチを取り込む | 利用者が push したブランチの先頭のコミットと base を求め、そのスナップショットを作る。ref は書かない |
| 版の記録を作る | 利用者のコミットを指す、署名付きの版の記録（タグ）を作る。ref に置くのは「ref を書く」 |

- アダプタは、[worker の内部 API](../worker-api.md) のクライアントである。git に触れるのは worker だけで、バックエンドは git を読まず、clone も作らない。
  - 変わるファイルの中身は、バックエンドが [スナップショット](../snapshot.md) から書き出して渡す。
  - アダプタは、「リビジョンを作る」と「ref を書く」を内部 API の「書く」に、「版の記録を作る」と「ref を書く」を「版を書く」に、それぞれ 1 回にまとめて送る。「ブランチを取り込む」は「ブランチを読む」で送る。
- 「ref を書く」が通ったら、worker は、新しいリビジョンのスナップショットと `latest` を作ってから応答する。そのため、応答のあとに読めば、書いたものが見える。
- リビジョンは、ポートの外からは不透明な文字列として扱う。
- 期待する値を「ない」にすると、ref がまだないときだけ書ける。

## 書く ref

| ref | 書くとき |
|---|---|
| `main` | 最初のリビジョン（ないことを期待）、反映（今の `main` を期待） |
| 版：apply request の識別子と版の番号 | 版を作るとき（ないことを期待）。版の記録を指す |
| 今の版：apply request の識別子と `head` | 作成（ないことを期待）、更新（今の版を期待）、close と反映（今の版を期待して消す）。版の記録を指す |
| 回答：人への依頼の識別子 | 回答するとき（ないことを期待） |

- バックエンドは、ref の名前を構造で渡す。git の ref のパスを組み立てるのは、アダプタである（[名前を付けたリビジョン](../../adapters/git.md)）。
  - なぜ：ref の置き方を、バックエンドに漏らさないため。

## 失敗の種類

- 「ref を書く」は、期待した値と違って書けなかったときに、ほかの失敗と区別できる形で、どの ref が違ったかを返す。
- バックエンドは、どの ref が違ったかで、次の動きを決める。

| 違った ref | 意味 | バックエンドの扱い |
|---|---|---|
| `main`（最初のリビジョン） | `main` がすでにある | 用意の続きの判定に進む（[repository の用意](../README.md)） |
| `main`（反映） | 別の反映か、owner や admin の直接の push が、先に `main` を進めた | `latest` を読み直して、やり直す（[反映の手順](../merge.md)） |
| 版 | 同じ番号の版がすでにある | 作成なら送り直しとして続ける。更新なら `version_conflict`（[apply request の作成と更新](../apply-request.md)） |
| 今の版 | 先に別の更新、close、反映が通った | `version_conflict` |
| 回答 | すでに回答がある | 送り直しかを確かめ、違えば `not_open` |

## 決まり

- `main` を作るのは、repository の用意（[バックエンド](../README.md) の「repository の用意」）だけである。
- `main` を進めるのは、[反映の手順](../merge.md) だけである。
- 用意を途中から続けるときの判定は、バックエンドが行う（[repository の用意](../README.md)）。
  - なぜ：判定はルールであり、ルールはバックエンドにだけ置くから。
