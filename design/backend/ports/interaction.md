# やりとり

バックエンドが、提案・レビュー・人への依頼を置く先として、プロバイダに何を求めるかを確かめるときに読む。
このポートを実装するのが、プロバイダである（[アダプタ](../../adapters/README.md)）。

プロバイダは、ルールを判定しない。受け取ったものを置き、イベントをバックエンドに伝えるだけである。

## repository

- repository の、やりとりの側を用意する。
  - バックエンドは、プロバイダが解釈する参照（provider_ref）を渡す。
  - provider_ref は、管理者がサーバの設定に登録したものである（[設定と秘密情報](../../adapters/README.md)）。
- ほかの操作は、どれも repository を指定して行う。

## 提案と版

- 提案（apply request）を作る。
- 提案に、新しい版を足す。
  - 版は、[木の読み書き](tree-read-write.md) のリビジョンを、不透明な参照として持つだけである。
- 提案と版を読む。
- 反映の失敗の理由を記録する。
- 提案を close する。理由と、close したセッションを記録する。
- 提案が反映されたことを記録し、提案を閉じる。
  - この操作を呼ぶのは、[反映の手順](../merge.md) だけである。

## レビュー

- レビューを記録する。
  - 種類（`approve`、`request_changes`、`comment`）、本文、レビューした版
  - reviewer のセッションと、使ったプロンプトのリビジョン
- 提案ごとのレビューを、記録した順に読む。

## 人への依頼

- 人への依頼を記録する（対象ノード、種類、本文、起票したセッション）。
- 回答を記録する（本文、回答した利用者）。
- 人への依頼を読む。

## イベント

- 提案、レビュー、人への依頼が変わったら、バックエンドに知らせる。
