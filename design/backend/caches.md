# キャッシュ

バックエンドと worker が、GitForge の一覧の API だけでは足りない情報を、どこから読むかを確かめるときに読む。
一覧をどの API で読むかは [一覧の読み](list-reads.md) に書く。

## 持つもの

| もの | 置く場所 | キー | 書く側 |
|---|---|---|---|
| GitForge の repository の識別子 | プロセスのメモリ | gitforge_ref | バックエンドと worker のそれぞれ |
| 権限を問い合わせた結果 | バックエンドのメモリ | トークンの SHA-256 と repository の名前 | バックエンド（[権限のキャッシュ](../settings/users.md#権限のキャッシュ)） |
| 記録の控え | 置き場の `keep/records/` | GitForge の repository の識別子 | worker（[記録の控え](verify/records.md)） |
| `latest` | 置き場 | repository の名前 | worker（[latest](snapshot/main.md#latest)） |

- 設定の DB には、キャッシュを置かない。
  - なぜ：設定の DB は、利用者が WebUI から変える設定の正本で、GitForge の写しを持つ場所ではないから（[設定の DB](../settings/database.md)）。
- 権限のキャッシュ、記録の控え、`latest` の決まりは、それぞれのページが正本である。このページには、一覧の読みでの使い方だけを書く。

## GitForge の repository の識別子

- 記録の署名と、記録の控えのキーに使う識別子である（GitHub の `node_id`、Forgejo の `id`）。
- プロセスは、gitforge_ref ごとに、最初に読んだ識別子をメモリに 10 分だけ持つ。
  - なぜ持つか：識別子は、名前の変更や owner の移動でも変わらないのに、1 回の要求の中で何度も `GET /repos/{owner}/{repo}` を呼んでいたから。
  - なぜ 10 分か：同じ名前で repository を消して作り直すと、識別子が変わる。その食い違いを、10 分までに収めるため。
- 識別子が食い違っているあいだは、新しい repository の記録の署名が合わない。記録は数えられず、警告になる（[記録](../adapters/records.md)）。
  - そのあいだは、消した repository の記録の控えも、同じ番号の apply request の記録として読まれうる。これは受け入れる危険である。
  - なぜ受け入れるか：repository を同じ名前で消して作り直すのは、まれな操作だから。作り直したあと 10 分待てば起きない。
- 失っても、次に読むときに問い合わせ直すだけである。プロセスの間では共有しない。
  - なぜ共有しないか：どのプロセスも同じ値を読むので、食い違わないから。

## 記録の控え

- 一覧の読みでは、記録とレビューを、記録の控えと、控えの読む位置より後のコメントの一覧（`issues/comments?since=`）を合わせて作る。
  - 控えの読む位置より前の、署名の合う記録は、すべて控えにある。そのため、合わせたものは、repository のコメントの一覧を全部読んだときと同じ記録を持つ。
  - GitForge から消された記録も、控えにあれば数える。1 件の読みと同じである（[記録の控え](verify/records.md)）。
  - 読む位置より後のコメントは、記録を読む間隔のあいだに書かれたものだけなので、ふつうは 1 ページである。
- 控えは、repository ごとに 1 つのキーに置く。バックエンドは、1 回の要求で 1 回だけ読む（[スナップショットの置き場](ports/snapshot-store.md)）。
- 控えは worker だけが書く。バックエンドは読むだけである。
- worker が止まっているあいだは、読む位置より後のコメントが増え、ページ送りが増える。記録は読み落とさない。

## 古くなったときと、正本とずれたとき

- GitForge の識別子は、10 分で捨て、問い合わせ直す。
- 記録の控えは、GitForge の今のコメントと合わせて使うので、控えが古くても、今の記録は読み落とさない。
- `latest` が古いあいだは、`prepared` が `false` に見える。worker が取り込めば直る。
- どのキャッシュも、正本の GitForge から作り直せるか、失っても次の読みで問い合わせ直す。記録の控えだけは、GitForge から消された記録を持つので作り直せない（[スナップショットの置き場](ports/snapshot-store.md)）。

## 複数のプロセス

- メモリのキャッシュは、プロセスごとに持ち、共有しない。バックエンドを何台並べても、互いに影響しない。
- 置き場のもの（記録の控え、`latest`）は、どのプロセスも同じものを読む。
