# キャッシュ

バックエンドと worker が、GitForge の一覧の API だけでは足りない情報を、どこから読むかを確かめるときに読む。
一覧をどの API で読むかは [一覧の読み](list-reads.md) に書く。

## 持つもの

| もの | 置く場所 | キー | 書く側 |
|---|---|---|---|
| 権限を問い合わせた結果 | バックエンドのメモリ | トークンの SHA-256 と repository の名前 | バックエンド（[権限のキャッシュ](../settings/users.md#権限のキャッシュ)） |
| 記録の控え | 置き場の `keep/records/` | GitForge の repository の識別子 | worker（[記録の控え](verify/records.md)） |
| `latest` | 置き場 | repository の名前 | worker（[latest](snapshot/main.md#latest)） |
| GitForge の repository の識別子 | worker のメモリ | gitforge_ref | worker |

- バックエンドは、新しいキャッシュを持たない。[状態を持たない](README.md#状態を持たない) は変えない。
  - GitForge の repository の識別子は、pull request の一覧から取るか、要求の中でだけ覚える（[一覧の読み](list-reads.md#どの一覧の-api-で読むか)）。
  - なぜ：識別子は記録の署名に使う。プロセスに持つと、同じ名前で repository を作り直したあと、古い識別子で署名した記録が残り、あとから直せないから。
- 設定の DB には、キャッシュを置かない。
  - なぜ：設定の DB は、利用者が WebUI から変える設定の正本で、GitForge の写しを持つ場所ではないから（[設定の DB](../settings/database.md)）。
- 権限のキャッシュ、記録の控え、`latest` の決まりは、それぞれのページが正本である。このページには、一覧の読みでの使い方だけを書く。

## worker の、GitForge の repository の識別子

- worker は、記録を読むたびに識別子を問い合わせず、gitforge_ref ごとにメモリに 10 分持つ。
  - なぜ持つか：記録を読むたびに問い合わせると、REST の回数が倍になり、repository が 30 個で installation の上限に近づくから（[費用と規模の見積もり](../estimates/README.md#github-アダプタ)）。
  - worker は記録を読むだけで、署名しない。識別子が古くても、記録を書き込む側を壊さない。
  - 同じ名前で repository を作り直したあとの 10 分は、新しい repository の記録の署名が合わず、控えに足されない。10 分たつと、新しい識別子の控えを、はじめから作る。

## 記録の控え

- 一覧の読みと 1 件の読みでは、記録とレビューを、記録の控えと、控えの読む位置より後のコメント（`issues/comments?since=`）を合わせて作る。
  - バックエンドも、worker と同じく、読む位置の 1 秒前から読む。同じ id のコメントは 1 つにし、控えにあるものは控えの中身を使う（`MergeComments`）。
  - 控えの読む位置より前の記録は、すべて控えにある。署名の合わないレビューの記録も、「無効」の印つきで控えにある（[記録の控え](verify/records.md)）。そのため、合わせたものは、repository のコメントの一覧を全部読んだときと同じ記録と、同じ鎖の切れを持つ。
  - GitForge から消された記録も、控えにあれば数える。
  - 読む位置より後のコメントは、記録を読む間隔のあいだに書かれたものだけなので、ふつうは 1 ページである。
- 控えは、読む位置と記録を 1 つのオブジェクトに持ち、worker が 1 回の書き込みで置き換える（[スナップショットの置き場](ports/snapshot-store.md)）。
  - なぜ：読む位置と記録を別に書くと、その間に読んだバックエンドが、記録を読み落とすから。
- バックエンドは、控えのオブジェクトがなければ、`since` を付けずに、repository のコメントを全部読む。遅いだけで、正しい。
- 控えは worker だけが書く。バックエンドは読むだけである。
- worker が止まっているあいだは、読む位置より後のコメントが増え、ページ送りが増える。記録は読み落とさない。
- 控えが記録 1 万件（10 MB ほど）を超えたら、要求ごとに読む量を見直す。

## 古くなったときと、正本とずれたとき

- 記録の控えは、GitForge の今のコメントと合わせて使うので、控えが古くても、今の記録は読み落とさない。
- `latest` が古いあいだは、`prepared` が `false` に見える。worker が取り込めば直る。
- worker の識別子は、10 分で捨て、問い合わせ直す。
- 記録の控えは、GitForge から消された記録を持つので、GitForge から作り直せない（[スナップショットの置き場](ports/snapshot-store.md)）。ほかのものは、失っても次の読みで問い合わせ直す。

## 複数のプロセス

- バックエンドは、プロセスの間で共有するキャッシュを持たない。何台並べても、互いに影響しない。
- 置き場のもの（記録の控え、`latest`）は、どのプロセスも同じものを読む。控えのオブジェクトは 1 回の書き込みで置き換わるので、読む側は、古いものか新しいものの、どちらか一方を読む。
