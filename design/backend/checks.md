# 差分の検査

apply request の差分を、バックエンドがどう検査するかを確かめるときに読む。
バックエンドは、どのプロバイダを使っても、同じ検査を行う。
ファイルの形は、[木のファイル配置](../files/README.md) に書く。

## 検査する時点

- apply request が作られたとき、または更新されたとき（ブランチの差分に対して）
- 反映する直前（最新の `main` に、版の差分を当てはめた木に対して）

検査は、もとの木（base）と、差分を当てはめたあとの木（head）の差分に対して行う。

- 検査は、[スナップショット](snapshot.md) の上で行う。ブランチの差分は、worker がスナップショットにしたものを使う。
- git のファイルを読み直さない。なぜ：git のファイルを解析して木にするのは、worker だけだから。
- 利用者は、ブランチに、どんなファイルの変化でも入れられる。そのため、下の「許すこと」以外の変化は、すべて拒む。

## 差分として許すこと

次の変化だけを許す。

- 新しい仮説とストーリーのディレクトリを、ファイルごと加える。
- 新しい検証結果のファイルを、`verdicts/` に加える。
- `inactivated.md` を、ストーリーのディレクトリに加える。
- `background.md` の末尾に、文章を加える。
  - head の内容が、base の内容で始まることを確かめる。
- `artifacts/sha256/` に、新しいファイルを加える。

## 差分として拒むこと

- `tree/` と `artifacts/sha256/` の外の、どんなファイルの変化も
  - 例：`.github/` や、リポジトリの直下のファイル
- 形の読めないファイル（front matter が壊れている、決まっていない項目がある、など）

- すでにあるファイルの変更（`background.md` の末尾への追加を除く）
- ファイルとディレクトリの削除
- ファイルとディレクトリの名前の変更

これにより、次の 2 つが守られる。

- append-only：一度加えたファイルは、変わらず残る（[監査](../../docs/architecture/README.md)）。
- 主文を変えないこと：`hypothesis.md` と `story.md` は、加えたあと変わらない（[操作](../../docs/apply-request/README.md)）。

## head の木で確かめること

- 新しいノードの識別子が、base の木と、今の `main` の木に、まだない。
  - 識別子は、クライアントが決める（[ファイルの配置](../files/layout.md)）。ぶつかったら、拒む。
- 交互に並ぶこと：`h-` の子は `s-` だけ、`s-` の子は `h-` だけである。
- 深さ：仮説が 24 段を超えない（[深さの上限](../files/parent-child.md)）。
- 根は 1 つ：`tree/` の直下に、仮説のディレクトリが 1 つだけある。
- ストーリーの子仮説は 1 つ以上：新しい `s-` には、`h-` が 1 つ以上ある。
- 文字数：主文、タイトル、概要の上限（[仮説とストーリーの木](../../docs/tree/README.md)）。
- 有効な検証結果は 1 つまで：[有効な検証結果](../files/layout.md) が、1 つの仮説に 2 つ以上ない。
- 差し替え：`supersedes` が指すのは、同じ仮説の、その時点で有効な検証結果である。
- 検証結果と active な子ストーリーを同時に持たない。
- 検証結果を持つ仮説の下に、新しいストーリーを作らない。
- inactive な部分木の下に、新しいストーリーを作らない。
- inactive な部分木の中の検証結果は、inactive になる前に葉だった仮説にだけ出す。
  - inactive になる前の状態は、`inactivated.md` が加わったリビジョンの 1 つ前の木で確かめる。ストーリーの [ノードの変更の一覧](snapshot.md) から、そのリビジョンの番号を求め、`history` で 1 つ前の SHA のスナップショットを読む。
- 部分木の引用：引用したリビジョンが、今の `main` のスナップショットの `history` にある。かつ、そのリビジョンのスナップショットの木に、指定した識別子のノードがある（[スナップショット](snapshot.md)）。
- artifact の引用：sha256 が、base の木の `artifacts` か、同じ版で加えるファイルにある。
- 回答のファイルの引用：sha256 が、署名の正しい回答のリビジョンの `artifacts` にあり、同じ版で同じファイルを加えている（[人への依頼の回答](../files/artifacts.md)）。
- artifact のファイル名が、中身のハッシュと一致する。
- artifact のファイルが、上限の大きさを超えない（[artifact](../../docs/tree/verdict.md)）。
- 加えた artifact は、加えた検証結果か、加えた回答のファイルから参照されている。
- 保存しない値（真偽値など）が、ファイルに書かれていない。

これらの不変条件の正本は、[仮説とストーリーの木](../../docs/tree/README.md) と [inactive 化](../../docs/tree/inactive.md) である。

## 値の計算

- バックエンドは、head の木から値を計算する（[真偽値の伝播](../../docs/tree/propagation.md)）。
- 計算した値は、ファイルに書かない。
- 論理レビューの材料や、着手できる作業の判定にも、同じ計算を使う。
