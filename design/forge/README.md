# 独自フォージ

GitHub を使わずに Logiforge を動かすときの、独自フォージ（GitHub の代わりになる、別のプロセスのサービス）を作るときと、運用するときに読む。
バックエンドから独自フォージをどう使うかは、[独自フォージのアダプタ](../adapters/forge.md) に書く。

## 役割

独自フォージは、GitHub を使う構成で GitHub が持つものを、代わりに持つ。

| 持つもの | GitHub を使う構成でのもの | ページ |
|---|---|---|
| git リポジトリ（bare） | GitHub リポジトリ | [git のホスティング](git-hosting.md) |
| 提案・版・レビュー・反映の失敗・人への依頼 | pull request と issue | [テーブル](tables.md) |
| 主体とトークン | GitHub のアカウントとトークン | [テーブル](tables.md) |

- 独自フォージは、ルールを判定しない。受け取ったものを置き、求められたら返すだけである。
  - なぜ：ルールはバックエンドにだけ置くから（[レイヤー構成](../architecture.md)）。
- 独自フォージの API の正本は、[openapi.yaml](openapi.yaml) である。
  - 範囲は、[独自フォージのアダプタ](../adapters/forge.md) が使う分だけにする。
  - なぜ：独自フォージは、バックエンドのためだけにあるから。使わない API は、作るものと確かめるものを増やすだけである。

## 主体

| 種類 | 使う者 | できること |
|---|---|---|
| `writer` | バックエンド | 独自フォージの API を使う。git リポジトリに push する |
| `user` | WebUI を使う利用者 | git リポジトリを読む |
| `client` | CLI を使う主体（エージェントか人） | git リポジトリを読む |

- `user` と `client` のトークンは、バックエンドの API で使う。バックエンドが、独自フォージに問い合わせて確かめる。
- 独自フォージの API と git への push は、`writer` だけに許す。
  - なぜ：`main` を進めるのは、バックエンドの [反映の手順](../backend/merge.md) だけだから。
- `user` と `client` には、git リポジトリを読むことを許す。
  - なぜ：既存の git の道具（clone、diff、履歴）で状態を扱えるようにするため（[木の置き場所](../../docs/architecture/README.md)）。
- すべての主体が、すべての repository を読める。
- 主体とトークンは、管理者が独自フォージのコマンドで登録する。
  - トークンの発行は、独自フォージの API の範囲外である。
  - なぜ：Logiforge の API でも、トークンの発行は範囲外だから（[認証](../api/README.md)）。

## データの置き場所

- テーブルは、1 つの SQLite ファイルに置く。
  - なぜ：書き込むのはバックエンドだけで、1 台のマシンで使う構成なので、1 本の書き込みで足りるから。
- git リポジトリは、bare リポジトリとして、設定したディレクトリに置く。
- SQLite ファイルのパスと、git リポジトリを置くディレクトリは、独自フォージの設定に書く。

## バックアップ

- 独自フォージのデータは、Logiforge の正本である。SQLite ファイルと、git リポジトリのディレクトリの両方を取る。
- 主体とトークンを失うと、誰も API を使えなくなる。バックアップから戻す。
