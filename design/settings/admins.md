# 管理者

誰が設定を変えられ、管理者をどう足すかを確かめるときに読む。
管理者という役割は、[役割](../../docs/roles/README.md#管理者) に書く。

## 管理者の決まり

- 管理者は、GitForge のアカウント名で決める。設定の DB の `admins` に置く（[設定の DB](database.md)）。
- 最初の管理者は、初回のセットアップでサインインした主体である（[初回のセットアップ](setup.md)）。
- 管理者は、ほかの管理者を足せる。外せる。
- 最後の 1 人は外せない。外そうとしたら、`validation_failed` を返す。
  - なぜ：管理者がいなくなると、WebUI から設定を変えられなくなるから。
- 自分を外すこともできる。ほかに管理者がいるときに限る。

## 管理者を確かめる

- 設定の API は、主体が次の両方を満たすときだけ受け付ける。満たさなければ `forbidden`（403）を返す。
  - WebUI のサインインで得たトークンである。
    - GitHub を使う構成：Logiforge の GitHub App のトークン（[GitHub アダプタの認証](../adapters/github.md#認証)）
    - Forgejo を使う構成：Logiforge の OAuth2 のアプリケーションのトークン（[Forgejo アダプタの認証](../adapters/forgejo.md#認証)）
    - なぜ：CLI のトークン（`gh auth login` のものなど）を盗まれても、設定を変えられないようにするため。
  - アカウント名が `admins` にある。大文字と小文字を区別せずに比べる。
- 管理者であることと、`user` であることは別である。
  - 管理者でも、`user` として登録されていなければ、repository を作れない。
  - 初回のセットアップでは、最初の管理者を `user` にも登録する。

## 管理者ができること

- 設定の画面で、[設定](README.md#設定の-db-に置くもの) を読み、変える（[設定の画面](../../docs/webui/settings.md)）。
  - 秘密は、読めない。入れ直すことだけができる。
  - なぜ：画面やログに出ると、漏れる場所が増えるから。
- 記録の署名の鍵を、新しく作る。新しい鍵を、書くときの鍵にする。
  - 古い鍵の公開鍵は、残す。なぜ：それまでの記録を確かめるため（[記録のコメント](../adapters/records.md#記録のコメント)）。
- 管理者は、木を変えない。apply request を承認しない。
  - なぜ：設定と、木の中身の判断を分けるため。木の変更は opener と reviewer の役割である（[役割](../../docs/roles/README.md)）。

## 記録

- 設定を変えたら、変えた管理者と時刻を、その行に残す（`updated_by`、`updated_at`）。
- バックエンドは、設定を変えるたびに、変えた設定の名前と管理者を、ログに出す。秘密の値は出さない。

## 管理者をすべて失ったとき

- 管理者のアカウントをすべて失ったら、サーバを動かす管理者が `logiforge settings add-admin <アカウント名>` で足す。
  - このコマンドは、設定の DB を直接書く。バックエンドの鍵は要らない。
  - なぜ：設定の DB を書けるのは、サーバを動かす環境を持つ人だけだから。
