# スナップショットの置き場のアダプタ

[スナップショットの置き場](../backend/ports/snapshot-store.md) のポートを、何で実装するかを確かめるときに読む。

## 2 つのアダプタ

| アダプタ | 置き場 |
|---|---|
| 手元のディレクトリ | バックエンドと worker を動かすマシンのディレクトリ |
| 静的ファイルストレージ | キーでファイルを読み書きできる、HTTP のストレージ |

- どちらの構成でも、どちらのアダプタも使える。選び方は、[組み合わせ](README.md#組み合わせ) に書く。

- どちらのアダプタも、置き場を読むだけである。
- 静的ファイルストレージは、特定の製品を前提にしない。
  - なぜ：キーで読み書きできれば、どのストレージでも動くようにするため。

## 手元のディレクトリ

- キーを、そのままディレクトリの中のパスにする。
- 書くときは、一時ファイルに書いてから名前を付け替える。
  - なぜ：読む側が、書きかけのファイルを読まないようにするため。

## 静的ファイルストレージ

- キーを、そのままストレージのキーにする。
- `latest`、ブランチの履歴、ブランチの名前の一覧は、条件付きの書き込み（ETag と `If-Match`、ないときは `If-None-Match: *`）で書く。条件付きの書き込みを持つストレージを使う。
- 書く鍵は、worker だけが持つ。バックエンドは、読む鍵だけを持つ。
- クライアントには公開しない。
  - なぜ：読む主体の認可を、バックエンドの [認可](../backend/README.md) に揃えるため。
- ストレージは、バックエンドから転送の費用なしで読める場所に置く。
  - 例：バックエンドと同じクラウドの、同じ地域のストレージ。または、外への転送が無料のストレージ。
  - なぜ：バックエンドはキャッシュを持たず、読む要求ごとに数百 KB のスナップショットツリーを読むから。転送に費用がかかると、読む量に比例して費用が増える（[費用と規模の見積もり](../estimates/README.md#読む量と費用)）。
- CDN などのキャッシュは、任意である。読むのが遅いことが問題になったときに置く。
  - CDN からバックエンドへの転送は、多くの CDN で、インターネットへの転送として費用がかかる。置くときは、その費用を見積もる。
  - 置くときは、SHA と sha256 のキーは長くキャッシュしてよい。`latest` と `repositories` は変わるので、キャッシュしない。

## 設定

- ディレクトリのパス、またはストレージの接続先と鍵は、起動時に渡す（[環境変数](../deploy/env.md)）。
  - なぜ設定の DB に置かないか：置き場の場所はホストに結び付き、読む鍵と書く鍵はプロセスごとに違うから（[起動時に渡すもの](../settings/README.md#起動時に渡すもの)）。
