# スナップショットの置き場のアダプタ

[スナップショットの置き場](../backend/ports/snapshot-store.md) のポートを、何で実装するかを確かめるときに読む。

## 2 つのアダプタ

| アダプタ | 使う構成 | 置き場 |
|---|---|---|
| 手元のディレクトリ | 独自フォージを使う構成 | バックエンドと worker を動かすマシンのディレクトリ |
| 静的ファイルストレージ | GitHub を使う構成 | キーでファイルを読み書きできる、HTTP のストレージ |

- 静的ファイルストレージは、特定の製品を前提にしない。
  - なぜ：キーで読み書きできれば、どのストレージでも動くようにするため。

## 手元のディレクトリ

- キーを、そのままディレクトリの中のパスにする。
- 書くときは、一時ファイルに書いてから名前を付け替える。
  - なぜ：読む側が、書きかけのファイルを読まないようにするため。

## 静的ファイルストレージ

- キーを、そのままストレージのキーにする。
- `latest` は、ストレージが条件付きの書き込み（ETag などで、今の値が期待したものと同じときだけ書く）を持てば、それで書く。
- 読み書きの鍵は、worker だけが持つ。バックエンドは、読む鍵だけを持つ。
- クライアントには公開しない。
  - なぜ：読む主体の認可を、バックエンドの [認可](../backend/README.md) に揃えるため。
- 速さが要るときは、ストレージの手前に CDN などを置く。
  - SHA と sha256 のキーは変わらないので、長くキャッシュしてよい。
  - `latest`、`refs`、`repositories` は変わるので、キャッシュしないか、短くする。

## 設定

- ディレクトリのパス、またはストレージの接続先と鍵は、設定に置く（[設定と秘密情報](README.md)）。
