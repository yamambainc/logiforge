# CAS アダプタ

[ファイルの保管](../backend/ports/file-storage.md) のポートを、CAS（内容アドレス方式のストレージ）でどう実装するかを確かめるときに読む。

## ローカルのディレクトリ

```
<CAS のディレクトリ>/
  sha256/<先頭 2 文字>/<残りの 62 文字>   中身
  tmp/                                  受け取り途中のファイル
```

置くときは、次の順に行う。

1. 受け取った中身を `tmp/` に書く。
2. 書きながら SHA-256（ハッシュ関数の 1 つ）を計算する。
3. 同じ名前のファイルがすでにあれば、`tmp/` のファイルを消して終える。
4. なければ、`sha256/` の位置に移し、読み取り専用にする。

- 一度置いたファイルは、書き換えない。
- 削除してよいのは、下の「参照されない中身」だけである。
  - なぜ：artifact を変えないこと（[artifact](../../docs/tree/verdict.md)）を守るため。

## S3（Amazon のオブジェクトストレージ）互換のストレージ

- キーは、`sha256/<先頭 2 文字>/<残りの 62 文字>` にする。
- 置く前に、同じキーがあるかを確かめる。あれば置かない。
- バケットには、上書きと削除をさせない設定（オブジェクトロックなど）をする。

## 参照されない中身

次のどれからも参照されない中身は、一定の期間のあと、管理者が消してよい。

- `main` にある検証結果
- open の apply request の版
- 人への依頼の回答

参照されている中身は、消さない。

- なぜ：反映されなかったアップロードが、たまり続けないようにするため。
