# メモリのキャッシュ

GitHub を使う構成で、[サーバの状態](../backend/ports/server-state.md) のポートを、サーバのメモリでどう実装するかを確かめるときに読む。

## 選んだ理由

- GitHub を使う構成では、サーバの状態は、すべて GitHub と git から作り直せる。
- サーバにファイルを持たなければ、バックアップも要らない。
  - なぜ：正本がサーバにないので、ファイルに残す理由がないから。

## 起動したとき

起動処理のあと、バックエンドは、次の順にサーバの状態を作り直す。

1. repository の登録を、サーバの設定から作る。
2. イベントのログを、`main` のコミットの trailer と、やりとりのデータから作る。
   - ログの世代は、新しく決める（[イベントの世代](../api/README.md)）。
3. 突き合わせの状態を、`main` のコミットの trailer から作る。

- Idempotency-Key は、再起動で消えてよい。
- 作り直すまでの間に届いた要求には、`503`（一時的に使えない）を返す。

## 制約

- バックエンドは、1 つのプロセスで動かす。
  - なぜ：プロセスごとに別のメモリを持つと、イベントのログの番号がそろわないから。
