# メモリのキャッシュ

GitHub を使う構成で、[サーバの状態](../backend/ports/server-state.md) のポートを、サーバのメモリでどう実装するかを確かめるときに読む。

## 選んだ理由

- GitHub を使う構成では、サーバの状態は、すべて GitHub と git から作り直せる。
- サーバにファイルを持たなければ、バックアップも要らない。
  - なぜ：正本がサーバにないので、ファイルに残す理由がないから。

## 起動したとき

起動処理は、要求を受け付ける前に、次の順にサーバの状態を作り直す。

1. repository の登録を、サーバの設定から作る。
2. 突き合わせの状態を、`main` のコミットの trailer から作る。

- Idempotency-Key は、再起動で消えてよい。
- 複数のプロセスで動かすときは、Idempotency-Key をプロセスごとに持つ。
  - そのため、送り直しが別のプロセスに届くと、二重に処理されることがある。
