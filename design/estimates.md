# 費用と規模の見積もり

GitHub を使う構成を、どれくらいの費用と規模で動かせるかを確かめるときに読む。
想定は、利用者とエージェントが数人から十数人、repository が数個から数十個である。

## 前提

- repository は 30 個、1 つの木のノードは 1,000 個ほどまでとする。
- 書き込み（版の作成と更新、レビュー、close、起票、回答、反映）は、全体で 1 時間に 100 件ほどまでとする。
  - そのうち反映（`main` への push）は、1 日に数十件から 100 件ほどとする。

## GitHub の API の回数

App のインストールの上限は、REST が 1 時間 5,000 回である（repository と利用者が増えると、12,500 回まで増える）。
主体のトークンの上限は、主体ごとに 1 時間 5,000 回である。

| 要求 | REST の回数 | 数える上限 |
|---|---|---|
| どの要求も（認証） | 2〜3 回（主体、team の所属、リポジトリの権限） | 主体ごと |
| 作業の一覧 | 2 回（open の PR と issue の一覧）＋ open の PR ごとに 1 回（レビュー）＋ 回答済みの依頼ごとに 1 回（コメント） | App |
| apply request を読む | 3 回（PR、レビュー、反映の失敗） | App |
| 木のノードを読む | 2 回（open の PR と issue の一覧） | App |
| 書き込み | 1〜3 回（PR やコメントを書く、ラベルを付ける） | App |
| worker | 0 回（git だけを使う） | なし |

- open の apply request が 50 件あると、作業の一覧 1 回で、App の REST を 50 回ほど使う。
  - 外の仕組みが、作業の一覧を repository 10 個について 1 分ごとに読むと、1 時間 3 万回ほどで、上限を超える。
  - 認証は、エージェントが 1 秒ごとに要求すると、主体ごとに 1 時間 7,000〜1 万回で、上限を超える。
- そのため、多くの人とエージェントが頻繁に読むと、GitHub の API のレート制限に当たる。

## 制約：レート制限は、今は考えない

- バックエンドは、やりとりと認証を、要求ごとに GitHub から読む。結果を保持しない（[状態を持たない](backend/README.md)）。
- 上の見積もりのとおり、読む頻度が高いとレート制限に当たる。今は、これを考えない。
- 当たるようになったら、次の 2 つで対処する。
  - worker が、やりとり（提案、レビュー、人への依頼）も静的ファイルに写し、バックエンドはそれを読む。GitHub を読むのは、repository ごとに 1 つの worker だけになる。
  - バックエンドが、短い期限の署名付きのトークンを発行し、認証の問い合わせを、期限ごとに 1 回にする。

## worker

- worker は、小さな常駐のコンテナ 1 つで足りる。
  - 仕事は、変わった repository の fetch と、スナップショットと ref の一覧を書くことだけである。
- clone は、artifact の中身を含むので、repository ごとに数十 MB から数百 MB である。
  - repository 30 個で、永続するストレージは、数 GB から 10 GB ほどである。
- git の `ls-remote` は、repository 30 個 × 1 分ごとで、1 日に約 43,000 回、1 回数 KB である。GitHub の API の上限には数えない。

## スナップショットの大きさ

- `main` のコミットの木は、ノード 1,000 個で、背景情報とレポートを含めて 1〜5 MB ほどである。
  - 圧縮して置くと、数百 KB から 1 MB ほどになる。
- 版と回答の木は、親からの差分だけなので、1 つ数 KB から数十 KB である。
- コミットの記録は、1 つ数 KB である。
- `main` のコミットごとに 1 つ置くので、反映 1,000 回の repository で、およそ 1 GB になる。
  - artifact の中身は、sha256 ごとに 1 つだけ置くので、コミットの数では増えない。
- 古いスナップショットを消さないのは、引用と履歴で過去の SHA を読むからである。

## 書き込みのたびの clone

- バックエンドは、書き込みの要求ごとに、深さ 1 で、ファイルの中身を取らない clone を作る（[git アダプタ](adapters/git.md)）。
  - 取るのは、ディレクトリの構造（git の tree）だけで、ノード 1,000 個の木で数百 KB ほどである。
- 要求が終われば消す。

## 読む量

- バックエンドはキャッシュを持たないので、読む要求ごとに、`latest`（数十バイト）と、`main` の木（圧縮して数百 KB から 1 MB）を置き場から読む。
  - 木を読む要求が 1 時間 1 万件なら、置き場から 1 時間に数 GB を読む。
- 置き場の手前に CDN などを置けば、SHA のキーは変わらないので、ほとんどが CDN で返る。
- `refs` は、repository ごとに数 KB から数十 KB で、版を読む要求ごとに読む。
