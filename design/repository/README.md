# Logiforge リポジトリ形式

木の状態を git リポジトリのファイルとして置くときに、ファイルの形と、core がそれをどう検査するかを確かめるために読む。
要件は [docs/](../../docs/README.md) が正本である。

この形式は、[データ構造](../data/README.md) とは別の案である。

- 構造化データの案では、木を DB の表に置く。
- この案では、木を git リポジトリのファイルに置く。

## 考え方

- 木の状態は、リポジトリの `main` ブランチにファイルとして置く。
- 変更は、ブランチの差分として出す。
  - 差分が [apply request](../../docs/apply-request/README.md) にあたる。
- 値（真偽）は、ファイルに保存しない。core が、ファイルから計算する。
  - なぜ：保存すると、ファイルと値が食い違わないようにする仕組みが要るから。
- 不変条件と、変更の仕方の決まりは、core が差分を検査して守る（[core の検査](checks.md)）。
