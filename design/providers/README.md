# プロバイダ

プロバイダを実装するときと、どちらのプロバイダを使うかを決めるときに読む。
プロバイダは、ルールを判定しない。受け取ったものを置き、イベントをバックエンドに伝えるだけである（[レイヤー構成](../architecture.md)）。

## インターフェース

プロバイダが提供するのは、次の 5 つだけである。

### repository

- repository を用意する。
  - 用意の仕方がプロバイダごとに違うので、インターフェースに含める。
  - GitHub アダプタでは、既存の空の GitHub リポジトリを登録する（[GitHub アダプタ](github.md)）。
  - 独自プロバイダでは、bare の git リポジトリを作る（[独自プロバイダ](native.md)）。
  - なぜ：repository をバックエンドの設定として扱うと、API から repository を用意できなくなるから。
- repository を一覧する。
- ほかの 4 つの操作は、どれも repository を指定して行う。

### 提案と版

- 提案（apply request）を、ブランチとして作る。
- ブランチにコミットを足して、新しい版を作る。
- 提案と版を読む。
  - 版ごとの head のコミットを返す。
  - base は持たない。バックエンドが `git merge-base <head のコミット> main` で求める。
- 反映の失敗の理由を記録する。
- 提案を close する。理由と、close したセッションを記録する。
- バックエンドの検査が通った提案を、`main` に反映する。
  - この操作を呼ぶのは、[反映の手順](../backend/merge.md) だけである。

### レビュー

- レビューを記録する。
  - 種類（`approve`、`request_changes`、`comment`）、本文、レビューした版
  - reviewer のセッションと、使ったプロンプトのリビジョン
- 提案ごとのレビューを、記録した順に読む。

### 人への依頼

- 人への依頼を記録する（対象ノード、種類、本文、起票したセッション）。
- 回答を 1 回だけ記録する（本文、添付、回答した利用者）。
- 人への依頼を読む。

### イベント

- 提案、レビュー、人への依頼が変わったら、バックエンドに知らせる。
- `main` に、反映の手順によらないコミットができたら、バックエンドに知らせる。

## 実装

- 使うプロバイダは、サーバの設定で 1 つに決める。
  - なぜ：repository ごとにプロバイダを選べると、組み合わせが増えて単純さを失うから。

| 実装 | 置き場所 | ページ |
|---|---|---|
| GitHub アダプタ | GitHub の PR、review、check、issue | [GitHub アダプタ](github.md) |
| 独自プロバイダ | 自前の DB と git リポジトリ | [独自プロバイダ](native.md) |

- 木は、どちらの実装でも git リポジトリに置く（[木のファイル配置](../files/README.md)）。
- 版を書いたセッションは、どちらの実装でもコミットの trailer に残る（[セッション ID の記録](../backend/README.md)）。

repository について対応しないことは、[木の形](../../docs/tree/README.md) に書く。
