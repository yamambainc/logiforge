# スナップショットツリーのビュワー

ビュワーを実装するときと、ビュワーの表示の決まりを確かめるときに読む。
画面の要件は、[木のビューア](../../docs/webui/tree-viewer.md) と [apply request の画面](../../docs/webui/history.md) が正本である。使う API は、[画面と API](screens.md) に書く。

## 3 つの表示

ビュワーは、同じスナップショットツリーを 3 つの形で示す。上の「アウトライン」「図」「3D」で切り替える。URL の `view` に持つ。

- アウトライン：行を字下げして並べる。このページに書く。
- 図：ノードと線で描き、ズームとパンができる。向きは横と縦がある（[スナップショットツリーの図](graph.md)）。
- 3D：層ごとの円錐に置き、回す・ズーム・パンができる（[スナップショットツリーの 3D](viewer-3d.md)）。

選んだノード、開いたノード、検索、絞り込み、重ねた apply request は、3 つの表示で同じものを使う。切り替えても変わらない。
検索と絞り込みの決まりは、[ビュワーの検索と絞り込み](viewer-search.md) に書く。

- なぜ 3 つか：アウトラインは多くのノードを速く読み比べられる。図は部分木の形と、値がどこから伝わるかをつかみやすい。3D は、すべて開いたときの全体の形（どの枝が大きく深いか、偽や未決がどこに固まっているか）を、回して見渡せる。

## ノードの読み方

- 開いたときに、`listNodes` を 1 回呼び、スナップショットツリーのすべてのノードを読む。部分木ごとには読まない。
  - なぜ：検索、絞り込み、閉じた部分木の件数は、すべてのノードがないと出せないから。
  - 部分木ごとに読む形（`root` と `depth`）にするなら、検索と、閉じた部分木の件数を、BE に足すことになる。
  - 応答は gzip で受け取る（[配り方](stack.md#配り方)）。
- 読んだノードから、ブラウザの中で索引を作る：識別子からノード、親から子の並び、部分木の葉の値の内訳。
  - 子の並びは、`listNodes` の応答の順（深さ優先）に従う。
- 詳細のパネルの中身は、選んだときに `getNode` で読む。
- この作りは、ノード 4,000 個までを扱う。想定（1 つのスナップショットツリーで 1,000 個ほど、[費用と規模の見積もり](../estimates/README.md#想定する規模)）の 4 倍である。
  - ノードが増えて先に重くなるのは、ブラウザではなく、応答の大きさと、BE が重ねる処理である。

### 取り込み中の読み直し

`snapshot_pending` が返ったら、「取り込み中」と示し、次のように読み直す。

- 間隔は 2 秒から始め、読み直すたびに 2 倍にする。最大は 30 秒である。
- 5 分たっても出なければ、読み直しをやめる。「worker が止まっている可能性があります」と示し、手で読み直すボタンを置く。
  - なぜ：worker が止まっていると、読み直しが終わらないから。

## 行の仮想化（アウトライン）

- 開いているノードを、深さ優先で 1 列の行に並べ、見えている範囲の行だけを描く。行の高さは 30 px で固定する。
  - なぜ：ノードが 4,000 個でも、描く行は数十に収まるから。
- 選んだ行が見えなくなったら、見える位置までスクロールする。

## 折りたたみ

- 折りたたみは、アウトラインと図で共通である。
- 開いたときは、根から 2 段（根のストーリーと、その子の仮説）までを開く。
- 閉じた部分木の行には、部分木のノード数と、葉の仮説の値の内訳の横棒を示す。
  - なぜ：開かなくても、どの部分木が大きく、どこに偽や未決が残るかが分かるから。
- 「すべて開く」と「閉じる」を置く。
- URL の `node` で開いたときは、そのノードのまわり（親、兄弟、1 段下の子）を最初に示す。祖先とそのノードを開いて選び、図ではまわりを収める（[まわりを収める](graph-navigation.md#まわりを収める)）。
  - なぜ：共有されたリンクを開いた人が、そのノードがどこにあり、何を持つかを、操作なしに見られるようにするため。

## ここから見る

あるノードを表示の根にして、その下だけを示せる。決まりは、[ここから見る](view-from-here.md) に書く。

## 色と印

| もの | 示し方 |
|---|---|
| 仮説 | 丸。値の色で塗る |
| ストーリー | 菱形。値の色で塗る |
| 値 | 行の右端の札。真は緑、偽は赤、未決は灰色で、文字（真、偽、未決）も添える |
| 要再検討 | 黄の札「要再検討」 |
| 審査中の apply request | 紫の札「AR」。2 件以上なら件数を添える |
| open の人への依頼 | 青の札「依頼」 |
| inactive | 行の文字を灰色にし、印を塗らない。ストーリーには札「inactive」 |

- 色だけに頼らず、形と文字を添える。なぜ：色の見分けにくい人にも読めるようにするため。
- 識別子は、先頭の 6 文字を行に示す。詳細のパネルには全体を示す。

## 詳細のパネル

- 上に、根から選んだノードまでの祖先を示す。押すと、そのノードを選ぶ。
- 示すものは、[木のビューア](../../docs/webui/tree-viewer.md#ノードの詳細) の一覧に従う。
- 子のノードと引用しているノードは、押すとビュワーでそのノードを選ぶ。
- 審査中の apply request と open の人への依頼は、識別子をリンクで示す。
  - 押すと、apply request の画面か、人への依頼の画面で、それを開く（[URL](screens.md#url)）。

## キーボード

アウトラインと図と 3D で、同じキーを使う（[図のキーボード](graph-navigation.md#キーボード)）。

| キー | 動き |
|---|---|
| `↑` `↓` | 前、次の行を選ぶ |
| `→` `←` | 開く、閉じる。閉じた行で `←` なら親を選ぶ |
| `/` | 検索に移る |
| `Esc` | 検索を消す |
| `n` `p` | apply request を重ねているとき、次、前の変わるノードを選ぶ（[差分の重ね表示](overlay.md#差分の重ね表示)） |
