# 最初に作る範囲

WebUI の実装を、どこまでを最初の 1 件にするかを確かめるときに読む。

## 最初に作るもの

最初の実装は 1 件にし、PR を次の 3 段に積み上げる。
どの段でも、作る画面をモバイルの幅でも使えるようにする（[モバイルの表示](mobile.md)）。

各段で、次の実機で操作を確かめる。図のピンチとホイールは、ブラウザごとに届き方が違い、ずれが起きやすいからである。

- iOS の Safari（iPhone、幅 375 px）
- Android の Chrome
- macOS のトラックパッド（2 本の指の移動とピンチ）

- なぜ 3 段か：1 つの PR が大きいと、レビューしにくいから。段ごとに、動くものを確かめられる。

### 1. ビュワー

- Forgejo の OAuth2 でのサインインと、BE の中継の 3 つの要求、その設定（[サインイン](auth.md)）。
- 応答のヘッダーと、ファイルの開き方（[スクリプトの注入への備えと、ファイルの開き方](security.md)）。
- `logiforge serve` から WebUI を配ること、応答のヘッダー、gzip（[配り方](stack.md#配り方)）。
- repository を選ぶこと（[repository の一覧](../../docs/webui/repositories.md) のうち、一覧と選択）。
- ビュワーの、次のもの（[スナップショットツリーのビュワー](snapshot-tree-viewer.md)）。
  - アウトラインと図（[スナップショットツリーの図](graph.md)）
  - 行の仮想化と、折りたたみ
  - 閉じた部分木の件数と、値の内訳の横棒
  - 色と印
  - 検索と絞り込み
  - 詳細のパネル
  - キーボードの操作
  - 取り込み中の読み直し
- `Repository` の `root_statement`（[足す API](screens.md#足す-api)）。

### 2. 重ね表示と過去の時点

- 差分の重ね表示と、過去の時点（[差分の重ね表示と過去の時点](overlay.md)）。
- `listCommits`（[足す API](screens.md#足す-api)）。

### 3. 残りの 4 画面

- repository の作成、人への依頼、apply request と履歴、ダッシュボード（[画面と API](screens.md)）。

## 後に回すもの

| もの | 後に回す理由 |
|---|---|
| 2 つの時点の比較（過去の時点どうし） | 差分の重ね表示と同じ作りで足せる。要件にない |
| 引用の関係の図 | 詳細のパネルの「引用」「引用されている」で、たどれるから |
| 検索の結果を、一覧で別に示すこと | 一致が多いと祖先の行が増える。使ってみて読みにくければ足す |
| 開いたノードを、ブラウザを閉じても覚えること | URL に選んだノードがあれば、開き直せるから |

## 試作

見た目と、ノード 4,000 個での動きを確かめるための試作を、ブランチ [proto/webui-viewer](https://github.com/yamambainc/hypothesis-verification-harness/tree/proto/webui-viewer/prototypes/webui-viewer) に置く。

- API のかわりに、サンプルのデータ（ノード 100 個と 4,000 個）を読む。形は `listNodes` の応答に合わせる。
- アウトラインと図、デスクトップとモバイルの表示を持つ。
- 試作は、`main` に入れない。実装は、この設計に従って `webui/` に作り直す。
