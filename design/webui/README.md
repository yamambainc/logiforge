# WebUI の設計

WebUI を実装するときと、WebUI のために BE の API を変えるときに読む。
WebUI の要件（画面と、利用者ができること）は、[docs/webui](../../docs/webui/README.md) が正本である。この設計は要件に従い、要件の内容は写さずにリンクで指す。

2. [サインイン](auth.md)：GitHub App か Forgejo の OAuth2 でのサインインと、トークンの持ち方
3. [サインインの流れ](signin-flow.md)：セットアップの画面を先に出すとき、authorize から戻るまで、サインインの画面を出すとき
4. [サインインの中継](oauth-relay.md)：BE がトークンの交換を中継する要求と、その決まり
5. [スクリプトの注入への備えと、ファイルの開き方](security.md)：応答のヘッダーと、文字やファイルの示し方
6. [画面と API](screens.md)：7 つの画面（セットアップと設定を含む）が、どの API を使うか。WebUI のための API
7. [スナップショットツリーのビュワー](snapshot-tree-viewer.md)：ノード 4,000 個でも使える作りと、表示の決まり
8. [ビュワーの検索と絞り込み](viewer-search.md)：検索、絞り込み、一致の示し方
9. [ここから見る](view-from-here.md)：あるノードを表示の根にして、その下だけを示す
10. [スナップショットツリーの図](graph.md)：ノードと線で描く表示。横と縦の向き

12. [スナップショットツリーの 3D](viewer-3d.md)：層ごとの円錐に置き、回す・ズーム・パンができる表示

セットアップと設定の画面が従う決まり（設定の DB、管理者）は、[設定](../settings/README.md) に書く。

## WebUI の決まり

- WebUI は、BE の API だけを使うクライアントである（[クライアントの要件との対応](../api/clients.md)）。
  - GitForge の API と、静的ファイルストレージを、直接は呼ばない。
  - なぜ：構成（Forgejo か GitHub か）の違いを、BE のアダプタだけに閉じ込めるため（[レイヤー構成](../architecture.md)）。
- WebUI は、スナップショットツリーを変えない。例外は repository の作成である（[WebUI](../../docs/webui/README.md)）。
- WebUI は、状態をサーバに持たない。表示の状態（開いたノード、検索の語）は、ブラウザの中と URL にだけ持つ。
  - なぜ：BE が状態を持たない決まりを崩さないため（[状態を持たない](../backend/README.md)）。

## 対応しないこと

- 多言語。表示は日本語だけである。
- ダークテーマ。
- 2 つの時点の比較（過去の時点どうし）。要件にない。
- 引用の関係の図。
  - なぜ：詳細のパネルの「引用」「引用されている」で、たどれるから。
- 検索の結果を、一覧で別に示すこと。一致したノードは、ビュワーの中で祖先と一緒に示す（[ビュワーの検索と絞り込み](viewer-search.md)）。
- 開いたノードを、ブラウザを閉じても覚えること。
  - なぜ：URL に選んだノードがあれば、開き直せるから。
