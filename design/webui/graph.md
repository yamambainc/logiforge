# スナップショットツリーの図

ビュワーの図（ノードと線で描く表示）を実装するときに読む。
アウトラインと共通の決まり（読み方、色と印、検索と絞り込み）は、[スナップショットツリーのビュワー](snapshot-tree-viewer.md) に書く。

## ワイヤフレーム

```
+------------------------------------------------------------------+
|                    +----------------------+                      |
|                 ,--| ◆ 早く価値を体験…  [偽]|(-)--- …              |
| +-------------+ /   +----------------------+                     |
| | ○ 新しいオン |(-)  +----------------------+                     |
| |  ボーディング…|---- | ◆ つまずきを取り…[偽]|(+)                  |
| +-------------+ \   |  s-m1em    +88 ▬▬▬  |                      |
|                  `--| ◇ 呼び戻しが効く [未決]|(-)--- …              |
| [＋][－][全体][◎] 51%                                            |
+------------------------------------------------------------------+
```

## 描き方

- SVG で描く。レイアウトと、ズームとパンは、自前で書く。ライブラリは足さない。
  - なぜ SVG か：文字、押せる範囲、CSS の色を、アウトラインと同じ書き方で扱えるから。描くノードは、画面に入るものだけ（数十個）なので、Canvas にする速さは要らない。
  - なぜ自前か：レイアウトは約 40 行、ズームとパンは約 100 行で、描画を含めても約 350 行で書ける。d3 の `d3-zoom` は `d3-selection` などを連れてくるうえ、DOM を自分で書き換えるので、React が持つ SVG と取り合いになる（[フレームワーク](stack.md#フレームワーク)）。

## レイアウト

- 左から右へ並べる。深さごとに列を分ける。
  - なぜ左から右か：主文は横に長いので、横に並べると重なるから。
- 見えている葉に、上から順に 1 つずつ縦の位置を割り当てる。親は、最初の子と最後の子の真ん中に置く。
- ノードの箱の大きさは、次のとおりである。

| | 幅 | 高さ | 列の間隔 | 行の間隔 |
|---|---|---|---|---|
| デスクトップ | 264 px | 72 px | 324 px | 86 px |
| モバイル | 212 px | 70 px | 260 px | 82 px |

- 箱には、印、主文かタイトル（2 行まで）、値の札、識別子の先頭、札（[色と印](snapshot-tree-viewer.md#色と印)）を示す。
- 子のあるノードには、右端に開閉のボタン（＋、－）を置く。閉じた部分木には、ノード数と、葉の値の内訳の横棒を示す。

## 描く範囲

- 開いているノードだけを描く。開いているノードの集まりは、アウトラインと同じものを使う（[折りたたみ](snapshot-tree-viewer.md#折りたたみ)）。
  - なぜ：ノード 4,000 個をすべて描くと、線が重なって読めないから。
- そのうち、画面と、その周り 200 px に入るノードと線だけを描く。
  - 試作では、ノード 4,000 個で、開いた段数によらず描いたノードは 13〜71 個で、描き直しは 2 フレーム以内だった。
- 縮小して 45% を下回ったら、文字を省き、形と色だけを描く。

## 最初の表示と収め直し

- 図を開いたときは、根を左端に寄せ、開いている段がすべて画面に収まるまで縮める。
  - 縮める下限は 45% である。なぜ：それより小さいと、文字を省くから（[描く範囲](#描く範囲)）。
  - 下限でも収まらなければ、根を縦の真ん中に置く。
  - 最初の表示には、[フォーカス](#フォーカス) を効かせない。なぜ：選んだノードを真ん中に置くと、根の左側が空き、右側が切れるから。
- 検索の語や絞り込みを変えたときも、同じ決まりで収め直す。
  - 続けて最初の一致が選ばれても、フォーカスでは動かさない。
  - なぜ：一致が深い枝に散らばると、図は右に長くなるから。一致を順に見るには、アウトラインを勧める。

## 操作

| 操作 | 動き |
|---|---|
| ノードを押す | 選ぶ。詳細を示す |
| ＋、－ を押す | 開く、閉じる |
| ドラッグ、1 本の指で動かす | パン |
| ホイール、トラックパッドの 2 本の指の移動 | パン。`Shift`＋ホイールは横 |
| `Ctrl`＋ホイール、トラックパッドのピンチ、2 本の指で広げる・つまむ | ズーム。範囲は 12〜250% |

- ドラッグとクリックは、動いた量で見分ける。3 px 以上動いたら、ノードを押したとみなさない。
- なぜホイールをパンにするか：トラックパッドの 2 本の指の移動もホイールとして届くので、ホイールをズームにすると、縦に動かすとズームし、横に動かすとパンすることになるから。

道具は、図の左下に横 1 列で置く。左下は、根の列の下で、ノードが少ないからである。

| 道具 | 動き | モバイル |
|---|---|---|
| ＋、－ | ズーム | 置かない。ピンチでできるから |
| 全体 | 開いている部分の全体を、画面に収める。下限は 12% | 置く |
| 選んだノードへ | 選んだノードを、画面の真ん中に動かす | 置く |
| ズームの値 | 今のズームを示す | 置く |

## フォーカス

- 選んだノードが画面の外にあれば、画面の真ん中に動かす。ズームが 85% より小さければ、85% にする。
  - アウトライン、検索の `Enter`、詳細のパネルのリンク、キーボードで選んだときに起きる。図の中で押したときは、もう見えているので動かない。

## キーボード

- 図にも、アウトラインと同じキーが効く（[キーボード](snapshot-tree-viewer.md#キーボード)）。
- `↑` `↓` は、アウトラインの行の並び（深さ優先）で、前と次のノードを選ぶ。図の上下の位置ではない。
  - なぜ：図とアウトラインで、同じキーが同じノードに動くようにするため。

## 検索、絞り込み、差分の重ね表示

- 示すノードは、アウトラインと同じである（[検索と絞り込み](snapshot-tree-viewer.md#検索と絞り込み)）。一致したノードは黄の枠、祖先は薄く示す。
- 差分の重ね表示の印は、アウトラインと同じ色を、箱の左端の線と背景に付ける（[差分の重ね表示](overlay.md#差分の重ね表示)）。
  - 消えるノードは、枠を点線にし、文字に取り消し線を引く。
  - 加わるノードへの線は緑、消えるノードへの線は赤の点線にする。
