# モバイルの表示

WebUI を、スマートフォンの幅で使えるように実装するときに読む。
画面ごとの中身は [画面と API](screens.md)、ビュワーの決まりは [スナップショットツリーのビュワー](snapshot-tree-viewer.md) と [図](graph.md) に書く。

## レイアウトの切り替え

| 幅 | レイアウト |
|---|---|
| 767 px 以下 | モバイル。1 列にし、詳細はボトムシートにする |
| 768〜1,279 px | 2 列。詳細のパネルの幅は 360 px |
| 1,280 px 以上 | 2 列。詳細のパネルの幅は 440 px |

- 切り替えは、CSS のメディアクエリで行う。JS では、詳細をボトムシートにするかどうかだけを、同じ幅で見分ける。
- 幅 375 px（iPhone SE と mini の幅）で、すべての画面を使えるようにする。
- 画面の高さは、`100vh` ではなく `100dvh` にする。
  - なぜ：iOS の Safari では、`100vh` はアドレスバーを隠したときの高さになり、下のタブが画面の外に出るから。
- 下のタブとボトムシートの下には、`env(safe-area-inset-bottom)` の余白を足す。`viewport` の meta には `viewport-fit=cover` を付ける。
  - なぜ：ホームバーのある端末で、ボタンがホームバーと重ならないようにするため。

## 操作を確かめる端末

図のピンチとホイールは、ブラウザごとに届き方が違い、ずれが起きやすい。そのため、次の端末で操作を確かめる。

- iOS の Safari（iPhone、幅 375 px）
- Android の Chrome
- macOS のトラックパッド（2 本の指の移動とピンチ）

## 画面の骨組み

- 上の帯には、repository の選択と、利用者だけを置く。
- 画面の切り替えは、下のタブ（スナップショットツリー、依頼、AR、状況）にする。
  - なぜ：片手の親指で届く位置だから。
- 一覧から選んだものは、画面全体で示し、左上に戻るボタンを置く。ビュワーだけは、ボトムシートにする。

## タッチ操作

- 押せるものは、縦横 40 px 以上にする。見た目が小さいもの（開閉のボタンなど）は、押せる範囲だけを広げる。
- ホバーでしか出ない情報を作らない。
- 2 本の指の操作は、図のズームだけに使う。ほかの場所では、ブラウザの拡大に任せる。
- 長押しとスワイプで行う操作は作らない。どの操作も、ボタンでできるようにする。
  - なぜ：見つけにくく、スクロールと取り違えやすいから。
- 検索の入力欄は、文字の大きさを 16 px 以上にする。
  - なぜ：iOS の Safari は、16 px より小さい入力欄に触れると、画面を拡大するから。

## ビュワー

- 道具の帯は、2 段にする。
  - 1 段目：「アウトライン」「図」「3D」の切り替えと、時点
    - 幅に収めるため、モバイルでは「アウトライン」を「一覧」と短く示す。
  - 2 段目：検索と、「絞り込み」のボタン
- 絞り込みは、「絞り込み」のボタンで、下から出るシートに示す。ボタンには、選んでいる絞り込みの数を示す。
  - なぜ：絞り込みを帯に並べると、帯が画面の高さの約 1/4 を使い、図とアウトラインが狭くなるから。
- アウトラインは、行の高さを 40 px、字下げを 1 段 12 px にする。識別子と、閉じた部分木の横棒は示さない。
- 図は、[図のノードの大きさ](graph.md#レイアウトと向き) のモバイルの値を使う。最初の表示は、向きごとの表に従う（[最初の表示と収め直し](graph-navigation.md#最初の表示と収め直し)）。道具は「全体」と「選んだノードへ」だけにし、縦横 40 px にする（[操作](graph-navigation.md#操作)）。
- 図の向きの既定は、横である（[レイアウトと向き](graph.md#レイアウトと向き)）。
- 3D は、1 本の指で回し、2 本の指でズームとパンをする。ラベルは 12 個までにし、画面の中に収め、選んだノードの道具と重ねない（[3D](viewer-3d.md#文字)）。
- 図と 3D には `touch-action: none` を付ける。
  - なぜ：付けないと、ブラウザが 1 本の指の移動をスクロールに、2 本の指をページの拡大に使ってしまうから。
- 詳細は、下から出るボトムシートにする。
  - ノードを押すと開く。高さは画面の 62% である。中はスクロールできる。
  - 右上の閉じるボタンで閉じる。閉じても、選んだノードは変わらない。

## ほかの画面

- repository の一覧：1 列のリストにする。作成は、画面全体のフォームにする。
- 人への依頼：一覧から選ぶと、本文と回答のフォームを画面全体で示す。添付は、端末のファイルの選択を使う。カメラで撮った写真も選べる。
- apply request と履歴：一覧から選ぶと、反映したあとの木を画面全体で示す。
- ダッシュボード：項目を縦に並べる。
