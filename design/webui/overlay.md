# 差分の重ね表示と過去の時点

ビュワーで、apply request を反映したあとの姿と、過去の時点の姿を示すところを実装するときに読む。
要件は [apply request と履歴](../../docs/webui/history.md) が正本である。表示の共通の決まりは、[スナップショットツリーのビュワー](snapshot-tree-viewer.md) に書く。

## 差分の重ね表示

open の apply request を選ぶと、ビュワーは、それを今の `main` に反映したあとの姿を示す。

- ビュワーの上の「AR を重ねる」で選ぶ。apply request と履歴の画面からも、`?apply_request=` で開ける。
- `listNodes` を、`apply_request` を付けて 1 回呼ぶ。今の `main` の `listNodes` の応答と、ブラウザの中で比べる。
  - なぜ比べる API を足さないか：どちらの応答もすべてのノードを持つので、比べるのは識別子で突き合わせるだけで済むから。
- 比べた結果で、行を次のように示す。

| 比べた結果 | 示し方 |
|---|---|
| 反映したあとにだけある | 行の左端に緑の線、札「追加」 |
| 値が変わる | 行の左端に黄の線、札「未決 → 真」のように前と後 |
| 値のほかが変わる（主文、背景情報、inactive、要再検討、有効な検証結果） | 行の左端に黄の線、札「変化」 |
| 反映したあとにない | 行は示せないので、上の帯に件数だけを示す |

- 値が変わるのは、差分の対象のノードだけではない。伝播で変わる祖先にも、同じ印を付ける。
  - なぜ：利用者が、反映すると根までどう変わるかを、反映の前に確かめるため（[反映したあとの木](../../docs/webui/history.md#反映したあとの木)）。
- 開いたときに、変わるノードの祖先を開き、最初に変わるノードを選ぶ。
- 絞り込みに「この AR で変わる」を足す。変わるノードとその祖先だけを示す。
- 詳細のパネルには、「この AR での変化」として、変わった項目の前と後を示す。
- 上の帯に、apply request の説明、識別子、ブランチ、追加・変化・消えるノードの件数を示す。

`listNodes` が次のエラーを返したら、スナップショットツリーのかわりに、理由を示す。

| code | 示すもの |
|---|---|
| `overlay_unsupported` | 「`main` 向きではないので、ツリーは表示できません」と、apply request の向き先 |
| `overlay_conflict` | 今の `main` に重ねられないことと、`detail` の衝突したパス |
| `snapshot_pending` | 「取り込み中」。数秒おきに読み直す |
| `not_open` | apply request が open でなくなったこと。apply request と履歴の画面へのリンク |

## 過去の時点

- `main` のコミットを選ぶと、`listNodes` を `commit` を付けて呼び、その時点の姿を示す。
- コミットは、apply request と履歴の画面で、`listCommits` の一覧から選ぶ（[画面と API](screens.md#足す-api)）。
- 上の帯に、コミットの番号と時刻を示し、今の `main` に戻るボタンを置く。
- 過去の時点では、審査中の apply request と open の人への依頼の札は、今のものである（[コミット](../api/README.md#コミット)）。そのため、過去の時点では、この 2 つの札を示さない。
