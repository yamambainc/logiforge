# 差分の重ね表示と過去の時点

ビュワーで、apply request を反映したあとの姿と、過去の時点の姿を示すところを実装するときに読む。
要件は [apply request と履歴](../../docs/webui/history.md) が正本である。表示の共通の決まりは、[スナップショットツリーのビュワー](snapshot-tree-viewer.md) に書く。

## 差分の重ね表示

open の apply request を選ぶと、ビュワーは、それを向き先の今の先頭に反映したあとの姿を示す。

- ビュワーの上の「AR を重ねる」で選ぶ。選べるのは、open の apply request である（`listApplyRequests` の `state=open`）。apply request と履歴の画面からも、`?apply_request=` で開ける。
- 重ねるのをやめると、今の `main` に戻る。重ねる・やめるは、ブラウザの履歴に積む。戻るで、前の姿に戻る。
- 次の順に読み、ブラウザの中で比べる。
  1. `listNodes` を、`apply_request` を付けて呼ぶ。応答の `commit` は、重ねた向き先のコミットである。
  2. その `commit` が、手元に読んである `main` の応答の `commit` と同じなら、手元の応答と比べる。
     - 向き先が `main` でないときは、応答の `commit` は向き先のブランチのコミットなので、いつも次の 3 で読み直す。
  3. 違えば、`listNodes` を `commit=<その SHA>` で読み直し、それと比べる。
  - なぜ：2 つの呼び出しのあいだに `main` が進むと、ほかの反映による変化が、この apply request の変化に混ざるから。
  - なぜ比べる API を足さないか：どちらの応答もすべてのノードを持つので、比べるのは識別子で突き合わせるだけで済むから。
- 比べた結果で、アウトラインの行を次のように示す。図での示し方は、[図](graph.md#検索絞り込み差分の重ね表示) に書く。

| 比べた結果 | 示し方 |
|---|---|
| 反映したあとにだけある | 行の左端に緑の線、札「追加」 |
| 値が変わる | 行の左端に黄の線、札「未決 → 真」のように前と後 |
| 値のほかが変わる（主文、背景情報、inactive、要再検討、有効な検証結果） | 行の左端に黄の線、札「変化」 |
| 反映したあとにない（消える） | 比べた向き先の応答での、もとの位置に行を残す。行の左端に赤の線、文字に取り消し線、札「消える」 |

- 値が変わるのは、差分の対象のノードだけではない。伝播で変わる祖先にも、同じ印を付ける。
  - なぜ：利用者が、反映すると根までどう変わるかを、反映の前に確かめるため（[反映したあとの木](../../docs/webui/history.md#反映したあとの木)）。
- 変化を、直接の変化と、伝播だけの変化に分ける。
  - 直接の変化：追加、消える、値と要再検討のほかの項目（主文、背景情報、inactive、有効な検証結果など）の変化。
  - 伝播だけの変化：値か要再検討だけが変わる。祖先に多い。
  - 最初に選ぶノード、図でまわりを収める範囲、前と次の変更は、直接の変化だけを使う。伝播だけの祖先には印を付けるが、たどらない。
  - なぜ：伝播だけの祖先は根まで続くので、まわりに入れると、全体を収めるのと変わらなくなるから。
- 要再検討だけが変わる行の札は「→ 要再検討」にする。
- 消えるノードは、ノード数と、閉じた部分木の件数と内訳に数えない。
- 開いたときに、直接に変わるノードの祖先を開き、最初に直接に変わるノードを選ぶ。URL に `node` があれば、それを選び、図ではそのノードのまわりを収める。
  - 図では、直接に変わるノードとその親のまわりを、最初に収める（[まわりを収める](graph-navigation.md#まわりを収める)）。
- 直接に変わるノードを、行の並び（深さ優先）で順にたどれる。上の帯の「前の変更」「次の変更」と、`p` `n` のキーで選ぶ。帯には「3 / 8」のように、今どれを見ているかを示す。
  - 検索、絞り込み、inactive を隠しているあいだは、今の行にある変化だけをたどり、帯の数もそれに合わせる。
  - なぜ：変わるノードが深い枝に散らばっていても、開き閉じをせずに、すべてを順に確かめられるようにするため。
- 重ねているあいだは、絞り込みに「この AR で変わる」を置く。変わるノードとその祖先だけを示す。
- 詳細のパネルには、「この AR での変化」として、変わった項目の前と後を示す。
- 消える行の位置は、比べた向き先の応答での親と、兄弟の並びで決める。消える部分木は、根だけでなく子孫も同じ印で残す。
  - なぜ：ノードが消えることは、レビューで最も見落としたくない変化の一つだから。
- 消える行の詳細は、`getNode` を、比べた向き先の `commit` を付けて読む。
  - なぜ：`apply_request` を付けると、反映したあとの姿にそのノードがないので、`not_found` になるから。
- 上の帯に、apply request の説明、識別子、ブランチ、向き先、比べた向き先のコミット、追加・変化・消えるノードの件数を示す。
- 「AR を重ねる」の選択肢には、ブランチと向き先を示す。一覧の応答には説明がないことがあるからである。
- 向き先が `main` でなければ、上の帯を黄にし、「`main` 向きではないので、検査していません」と示す（[反映したあとの木](../../docs/webui/history.md#反映したあとの木)）。
  - 詳細のパネルの「この AR での変化」にも、同じ注意を示す。
  - 向き先が `main` でないときは、衝突を判定しない（[向き先に重ねる](../backend/snapshot/branch.md#向き先に重ねる)）。本当の衝突は、GitForge の画面で分かる。
- 向き先が `main` でないとき、`getNode` を `apply_request` を付けて呼ぶと、1 回に約 1 秒かかる。向き先の木を作る分と、重ねる分である。
  - そのため、ノードを押したら、`listNodes` の応答で分かる項目（主文やタイトル、値、札、この AR での変化）を先に示し、`getNode` の応答が来たら、検証結果や履歴などの残りを示す。

`listNodes` が次のエラーを返したら、スナップショットツリーのかわりに、理由を示す。

| code | 示すもの |
|---|---|
| `overlay_conflict` | 今の `main` に重ねられないことと、`detail` の衝突したパス。向き先が `main` のときだけ返る |
| `not_found` | 向き先のブランチが消えたこと（apply request がなくなったときも同じ） |
| `snapshot_pending` | 「取り込み中」と示し、読み直す（[取り込み中の読み直し](snapshot-tree-viewer.md#取り込み中の読み直し)） |
| `not_open` | apply request が open でなくなったこと。apply request と履歴の画面へのリンク |

## 過去の時点

- `main` のコミットを選ぶと、`listNodes` を `commit` を付けて呼び、その時点の姿を示す。
- コミットは、ビュワーの上の「時点」で、`listCommits` の新しい 50 個から選ぶ。古いものは、apply request と履歴の画面で、`listCommits` の一覧から選び、`?commit=` で開く（[画面と API](screens.md#webui-のための-api)）。
  - 選択肢には、コミットの番号、時刻、反映した apply request を示す。
  - 上の帯の番号と時刻は、選択肢の 50 個から引く。なければ、SHA だけを示す。
- 時点を変えても、選んでいたノードがその時点にあれば、選んだままにする。
- 上の帯に、コミットの番号と時刻を示し、今の `main` に戻るボタンを置く。
- 過去の時点では、審査中の apply request と open の人への依頼の札は、今のものである（[コミット](../api/README.md#コミット)）。そのため、過去の時点では、この 2 つの札を示さない。絞り込みの「審査中の AR」「open の依頼」も出さない。
- 上の帯に、過去の時点では札を示さないことも書く。
