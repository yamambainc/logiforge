# スナップショットツリーの 3D

ビュワーの 3D の表示を実装するときに読む。
アウトラインと図と共通の決まり（読み方、色と印、検索と絞り込み、共通の状態）は、[スナップショットツリーのビュワー](snapshot-tree-viewer.md) に書く。

## 置き方

層ごとの円錐に置く。

- 根を頂点に置き、深さごとに 1 つ下の層に置く。層の間隔は 70 である（three.js の単位）。
- 各層では、根の真下を中心にした円の上に置く。円の半径は、深さ × 90 である。
- 角度は、根に 360° を割り当て、子に、見えている葉の数に比例して親の範囲を分ける。ノードは、自分の範囲の真ん中に置く。
- なぜこの置き方か：
  - 深さが高さになるので、回しても、上が根で下が深い、という向きを失わない。
  - 部分木は、角度の範囲（扇形）にまとまるので、回しても、同じ部分木のノードが離れない。重なりもない。
  - 計算はノードの数に比例し、毎回同じ形になる。開閉のたびに形が揺れない。
- 選ばなかった案：
  - 根を中心にした放射状（球）：上下の手がかりがなく、回すと、どちらが根の側かを見失いやすい。
  - 力学で広げる配置：ノード 4,000 個では落ち着くまでに時間がかかり、開閉のたびに形が変わる。

## 描き方

- three.js（0.187）で描く。
  - なぜライブラリを足すか：カメラ、回すとズームとパン（マウスと指）、ノードを押したときの当たり判定、たくさんの同じ形を 1 回で描くこと（instancing）を、自前で書くと数千行になるから。
  - 回す・ズーム・パンは、three.js の `OrbitControls` を使う。
  - 大きさは、試作のビルドで、3D の部分（three.js を含む）が gzip で約 143 KB である。
- 3D を開いたときだけ、3D の部分を読み込む（React の `lazy` によるコード分割）。アウトラインと図しか使わない利用者は、読み込まない。
- 仮説は球（80 面）、ストーリーは正八面体（8 面）で描き、形ごとに 1 回で描く（`InstancedMesh`）。親子の線は、1 本の `LineSegments` にまとめる。
  - なぜ面を少なくするか：ノード 4,000 個でも、端末の GPU の負担を小さくするため。
- 描くのは、カメラが動いたときと、ノードや色が変わったときだけである。止まっているあいだは描かない。
  - なぜ：止まっているあいだに電池を使わないため。

## 描く範囲

- 開いているノードだけを置く。開いたノードの集まりは、アウトラインと図と同じものを使う（[折りたたみ](snapshot-tree-viewer.md#折りたたみ)）。
- 閉じた部分木は、ノード数に応じて大きく描く（大きさは 1 + log10(ノード数) × 0.55 倍）。
- 「すべて開く」で、ノード 4,000 個をすべて置ける（下の「性能」）。

## 色と印

- 色は、アウトラインと同じく値で決める（真は緑、偽は赤、未決は灰色、inactive は薄い灰色）（[色と印](snapshot-tree-viewer.md#色と印)）。
- 形は、仮説が球、ストーリーが正八面体である。2D の丸と菱形に合わせた。
- 選んだノードには、青い輪を付ける。
- 検索で一致したノードには、黄の半透明の殻を重ねる。絞り込みで祖先として出したノードは、色を薄くする。
- 差分の重ね表示では、加わるノードに緑、値などが変わるノードに黄、消えるノードに赤の殻を重ね、消えるノードの色は薄くする。加わるノードへの線は緑、消えるノードへの線は赤にする（[差分の重ね表示](overlay.md#差分の重ね表示)）。

## 文字

- 主文とタイトルは、画面の上に重ねた HTML のラベルで示す。WebGL の中には描かない。
  - なぜ：日本語の文字を、ぼやけずに、フォントのまま出せるから。
- ラベルを出すのは、カメラに近い順に、デスクトップで 28 個、モバイルで 12 個までである。根と、選んだノードには、いつも出す。
  - ほかのラベルと重なるものは出さない。ラベルの幅は、文字数から見積もる。
  - 文字は 16 字までにし、それより長いものは「…」で切る。全文は、詳細のパネルで読む。
  - なぜ：ノード 4,000 個のラベルをすべて出すと、重なって読めないから。近づくと、近いノードのラベルが出る。

## 操作

| 操作 | マウス | 指 |
|---|---|---|
| 回す | 左ドラッグ | 1 本の指で動かす |
| ズーム | ホイール | 2 本の指で広げる・つまむ |
| パン | 右ドラッグ | 2 本の指で動かす |
| 選ぶ（詳細を示す） | 押す | 押す |
| 開く・閉じる | ダブルクリック、または選んだノードの横の「開く」「閉じる」 | 選んだノードの横の「開く」「閉じる」 |

- 押すのとドラッグは、動いた量で見分ける。5 px 以上動いたら、押したとみなさない。
- キーボードは、図と同じである（[図のキーボード](graph-navigation.md#キーボード)）。
- 画面の左下に、操作の短い案内を出す。

## 最初の表示とフォーカス

- 3D を開いたときは、開いている部分の全体が入るように、少し上から見下ろす位置にカメラを置く。
- 検索の語や絞り込みを変えたときも、同じ決まりで置き直す（[図の最初の表示と収め直し](graph-navigation.md#最初の表示と収め直し)）。
- 選んだノードが画面の外にあれば、カメラの向きと距離を変えずに、そのノードを真ん中に動かす。最初の表示には効かせない。

## 性能

試作で、ノード 4,000 個を、回し続けて測った（headless Chrome）。

| 端末 | 開いた範囲 | フレームレート | 1 フレームの JavaScript |
|---|---|---|---|
| デスクトップ（1440 × 900） | 3 段（26 個） | 60 fps | 約 0.7 ms |
| デスクトップ（1440 × 900） | すべて（4,000 個） | 約 7 fps | 約 2.1 ms |
| モバイル（375 × 812、CPU を 4 倍遅く） | 3 段（26 個） | 約 53 fps | 約 1.3 ms |
| モバイル（375 × 812、CPU を 4 倍遅く） | すべて（4,000 個） | 約 5 fps | 約 12.3 ms |

- この headless Chrome の WebGL は、SwiftShader（GPU を使わず CPU で描く）である。そのため、すべて開いたときの遅さは、CPU で三角形を塗る時間であり、GPU のある端末の数字ではない。
- JavaScript の時間（ラベルの選び直しを含む）は、CPU を 4 倍遅くしても 1 フレーム約 12 ms で、60 fps の 16.7 ms に収まる。
- GPU のある端末での、すべて開いたときのフレームレートは、実機で測る（[最初に作る範囲](first-release.md)）。30 fps を下回るなら、次の順に軽くする。
  1. ピクセル比を 1 にし、アンチエイリアスを切る。
  2. 遠いノードを点で描く。

## WebGL が使えないとき

- WebGL の描画を作れなければ、「この端末では 3D を表示できません」と示し、図で見るボタンを置く。
- 3D の部分の読み込みに失敗したときも、同じに示す。
