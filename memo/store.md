# ストアと並行性の案

ストアと並行性の方式を設計するときに、出発点として使う。
満たすべき性質は [全体構成](../docs/architecture/README.md) が正本である。

## ストア

- 初めは SQLite を使い、規模が大きくなったら Postgres に移す。
- artifact は、ローカルの CAS ディレクトリに置く。規模が大きくなったら、S3 互換のストレージに移す。
- 履歴はイベントソーシングで持ち、任意のリビジョンを再現する。
- git をそのまま使う方式は採らない。
  - 理由：木の不変条件を、確実に守らせたいから。
- 必要なら、git 形式へのエクスポートを付ける。

## 並行性

- AR には、`base_revision` による楽観ロックをかける。
- タスクは、リースで排他する。リースが切れたら、別の担当に回す。
- 適用は、トランザクションで行う。
- API への重複した要求は、idempotency key で 1 回分として扱う。

## 性能

- 想定する規模の木で、表示と再計算が対話的に使える速さで終わること。
- 規模と目標値は、設計のときに決める。
