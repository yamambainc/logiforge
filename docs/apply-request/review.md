# 論理レビュー

apply request の論理レビューが、どう起動し、何を確かめるかを引くために使う。

## 起動

- 論理レビューは、[apply request](README.md) が open になったとき、または更新されたときに起動する。
  - GitHub の required status check と同じ扱いである。
- 論理レビューは、起動のたびに新しいコンテキストで行う、使い捨てのレビューである。
  - なぜ：常駐するレビュアーと違い、前のレビューの文脈に引きずられないから。
  - なぜ：同じ材料なら、判断を再現しやすいから。
- reviewer に渡すのは、次のものだけである。
  - apply request の差分
  - 差分が参照するノード
- レビューのプロンプトは、リポジトリに置く。
  - プロンプトは差し替えられる。
  - 標準のプロンプトを 1 つ同梱する。

opener と reviewer を分ける決まりは、[役割](../roles/README.md) に書く。

## ストーリーの作成

`story.create` では、次のことを確かめる。

- 子仮説がすべて真なら、親仮説が真になるか（十分性）。
- 隠れた前提がないか。
- 兄弟ストーリーや祖先と、矛盾しないか。
- 子仮説どうしが、重なっていないか。
- 子仮説どうしが、循環していないか。

## 検証結果

`verdict.submit` では、次のことを確かめる。

- その仮説を、葉のまま直接検証してよい大きさか。
  - 単一の検証で真偽を決められない仮説は、ストーリーを立てて分解させる。
- 根拠が、値を支えているか。
- プログラムによる検証なら、再現できるか（[artifact](../tree/verdict.md)）。
- 引用が正しいか。
- 人の記入から作った検証結果なら、記入の内容に忠実か（[PVR](../threads/README.md)）。

## inactive 化

`story.inactivate` では、次のことを確かめる。

- 理由に書かれた欠陥が、本当に重大か。

## 偽と結論する

[偽と結論する](../tree/falsification.md) apply request では、次のことを確かめる。

- 仮説を直接否定する証拠があるか。
  - 「別のストーリーが見つからない」だけでは、偽と結論させない。
- その仮説の値が、true でないか。
  - true なら、根拠のどこかが反証と食い違っている。
  - その場合は先に、原因のストーリーを inactive にさせるか、誤った検証結果を差し替えさせる。

## 背景情報への追加

`node.edit` では、次のことを確かめる。

- 加えた文章が、主文の意味を変えていないか。
