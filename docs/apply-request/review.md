# Reviewer の審査観点

Reviewer が [Apply Request](README.md) を審査するときに、何を確かめるかを引くために使う。

## ストーリーの作成

`story.create` では、次のことを確かめる。

- 子仮説がすべて真なら、親仮説が真になるか（十分性）。
- 隠れた前提がないか。
- 兄弟ストーリーや祖先と、矛盾しないか。
- 子仮説どうしが、重なったり循環したりしていないか。

## 検証結果

`verdict.submit` では、次のことを確かめる。

- その仮説を、直接検証してよい大きさか。
  - 単一の検証で真偽を決められない仮説は、ストーリーを立てて分解させる。
  - 終端かどうかの判断は、この審査で行う。
- 根拠が、値を支えているか。
- プログラムによる検証なら、再現できるか（[artifact](../tree/verdict.md)）。
- 引用が正しいか。
- 人の記入から作った検証結果なら、記入の内容に忠実か（[PVR](../threads/README.md)）。

## inactive 化

`story.inactivate` では、次のことを確かめる。

- 理由に書かれた欠陥が、本当に重大か。

## 偽と結論する

[偽と結論する](../tree/falsification.md) AR では、次のことを確かめる。

- 仮説を直接否定する証拠があるか。
  - 「別の道筋が見つからない」だけでは、偽と結論させない。
- その仮説の値が、true でないか。
  - true なら、根拠のどこかが反証と食い違っている。
  - 先に、原因のストーリーを inactive にするか、誤った検証結果を差し替えさせる。

## 背景情報への追加

`node.edit` では、次のことを確かめる。

- 加えた文章が、主文の意味を変えていないか。
