# 検証結果と引用

葉の仮説に、値と根拠をどう付けるかを確かめるときに読む。

## 検証結果

- 検証結果は、値（`true` または `false`）とレポートの、1 対 1 の組である。
  - レポートのない値は出せない。
  - なぜ：すべての値を、根拠から辿れるようにするため。
- 検証結果を出せるのは、葉の仮説だけである（[葉と検証結果](README.md)）。
- 検証結果は、[apply request](../apply-request/README.md) の `verdict.submit` で出す。
- 検証結果は差し替えられる。
  - 古い検証結果は、履歴に残る。
  - 1 つの検証結果で、同じ仮説の有効な検証結果を、まとめて差し替えられる。
    - なぜ：有効な検証結果が 2 つになった仮説（[反映](../apply-request/README.md) の確認と反映の間に起きうる）を、1 つの差分で直せるようにするため。
- inactive な部分木の中では、inactive になる前に葉だった仮説にだけ、検証結果を出せる。
  - なぜ：inactive にされた時点で進行中だった作業を、記録として残すため。
  - その値は、伝播しない（[inactive 化](inactive.md)）。
- 葉を直接検証してよいかの判断は、[論理レビューの審査観点](../apply-request/review-criteria.md) に書く。

## レポート

レポートには、次のものを含められる。

- 本文
- artifact
- 引用

## artifact

artifact は、レポートが参照する根拠物である。次のようなものがある。

- 参考文献からの引用とリンク
- プログラムと、その実行結果
- データ
- 人への依頼の回答（[人への依頼](../human-requests/README.md)）

artifact の置き方は、次の 2 種類だけである。

- ファイル：repository の git リポジトリに入れる、小さなファイル
- リンク：外の URL
  - 中身の sha256（ハッシュ値）を書いておけば、検証のときに照合する。

ファイルの大きさは、1 つあたり 10 MiB までにする。

- なぜ：PVR の回答に添えるスマートフォンの写真（数 MiB）を、そのままファイルにできるようにするため。
- なぜ：それ以上の大きさのファイルが増えると、git リポジトリのクローンが遅くなるため。

artifact の扱いは、次のとおり。

- artifact は、変更しない。
  - なぜ：検証をあとから再現できるようにするため。
- プログラムによる検証では、次のものを artifact として残す。
  - コード
  - 入力
  - 実行環境の情報
  - 出力

## 引用

レポートからは、次のものを引用できる。

- ほかの仮説の artifact
- `main` のコミットを固定した部分木
  - なぜ：引用したときの根拠を、あとからそのまま辿れるようにするため。

引用できるのは、同じ repository の中のものだけである。

- ほかの repository から移した repository では、移す前に書いた引用は、元の repository のコミットを指したまま読める。
- 移した repository で新しく書く引用は、移した先のものだけを指す。

## 流用

検証済みの仮説 X を、別のストーリーで使いたいときは、次のようにする。

1. 新しいストーリーの下に、新しい仮説 X′ を作る。
2. X′ に、X の部分木を引用するだけのレポートを付けて、true の検証結果を出す。
   - X が葉なら、X の検証結果を引用する。
   - X が葉でなければ、X を true にしている子ストーリーの配下にある検証結果を引用する。

流用は、引用の使い方の 1 つであり、特別な仕組みではない。

## 引用元の変化

引用元の変化とは、引用している部分木の中で、次のどちらかが起きることをいう。

- 検証結果の差し替え
- ストーリーの inactive 化

引用元が変化しても、引用している仮説の値は、自動では変えない。

- なぜ：引用元の変化が結論に影響するかどうかは、判断が要るから。

見直して値を変える必要がなかったときも、検証結果を出し直すと、引用元の変化は解消する。

## 対応しないこと

- repository をまたぐ引用
  - ほかの repository の根拠を使いたいときは、その中身を artifact に含めて参照する。
- 10 MiB を超えるデータの保管と配布
  - 利用者やエージェントが別の場所で管理し、リンクの artifact で参照する。
  - なぜ：大容量データの保管と配布は Logiforge の責務の外。仕組みを持つと、ポート・アダプタ・秘密情報・掃除が増えるため。
