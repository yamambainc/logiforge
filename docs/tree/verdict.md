# 検証結果と引用

葉の仮説に、値と根拠をどう付けるかを確かめるときに読む。

## 検証結果

- 検証結果は、値（`true` または `false`）とレポートの、1 対 1 の組である。
  - レポートのない値は出せない。
  - なぜ：すべての値を、根拠から辿れるようにするため。
- 検証結果を出せるのは、葉の仮説だけである（[葉と検証結果](README.md)）。
- 検証結果は、[Apply Request](../apply-request/README.md) の `verdict.submit` で出す。
- 検証結果は差し替えられる。
  - 古い検証結果は、履歴に残る。
- inactive な部分木の中では、inactive になる前に葉だった仮説にだけ、検証結果を出せる。
  - なぜ：inactive にされた時点で進行中だった作業を、記録として残すため。
  - その値は、伝播しない（[inactive 化](inactive.md)）。
- 葉を直接検証してよいかの判断は、[Reviewer の審査観点](../apply-request/review.md) に書く。

## レポート

レポートには、次のものを含められる。

- 本文
- artifact
- 引用

## artifact

artifact は、レポートが参照する根拠物である。次のようなものがある。

- 参考文献からの引用とリンク
- プログラムと、その実行結果
- データ
- 人による記入（[PVR](../threads/README.md) への記入など）

artifact の扱いは、次のとおり。

- artifact は、中身のハッシュで識別する。
- artifact は、変更しない。
  - なぜ：検証をあとから再現できるようにするため。
- プログラムによる検証では、次のものを artifact として残す。
  - コード
  - 入力
  - 実行環境の情報
  - 出力

## 引用

レポートからは、次のものを引用できる。

- ほかの仮説の artifact
- リビジョンを固定した部分木
  - なぜ：引用したときの根拠を、あとからそのまま辿れるようにするため。

## 流用

検証済みの仮説 X を、別のストーリーで使いたいときは、次のようにする。

1. 新しいストーリーの下に、新しい仮説 X′ を作る。
2. X′ に、X の部分木を引用するだけのレポートを付けて、true の検証結果を出す。
   - X が葉なら、X の検証結果を引用する。
   - X が葉でなければ、X を true にしている子ストーリーの配下にある検証結果を引用する。

流用は、引用の使い方の 1 つであり、特別な仕組みではない。

## 引用元の変化

引用元の変化とは、引用している部分木の中で、次のどちらかが起きることをいう。

- 検証結果の差し替え
- ストーリーの inactive 化

引用元が変化しても、引用している仮説の値は、自動では変えない。

- なぜ：引用元の変化が結論に影響するかどうかは、判断が要るから。
