# 仮説とストーリーの木

木の形と、どの変更でも保たれる不変条件を確かめるときに読む。

## 木の形

- 根は仮説である。
- 木は、repository ごとに 1 つだけある。
  - repository は、1 つの問い（根の仮説）とその木を収める単位である。
  - repository は、[GitForge](../concepts/glossary.md) の 1 つの git リポジトリか、git リポジトリの中の 1 つのディレクトリに対応する。
  - 1 つの Logiforge は、複数の repository を扱える。
  - 別の問いを扱いたいときは、repository をもう 1 つ作る。
  - なぜ：仮説とストーリーは、1 つの木構造として表すものだから。
- 1 つの木に、根は 1 つだけある。
  - 根は、究極的な問いを表す。
- 仮説の子は、ストーリーである。
- ストーリーの子は、仮説である。
  - そのため、仮説とストーリーは交互に並ぶ。
- 1 つの仮説の下に、ストーリーは 0 個以上ある。複数あってもよい。
- 1 つのストーリーの下に、仮説は 1 個以上ある。
- 木は厳密な木で、ノードを共有しない。
  - 別の場所の結果を使いたいときは、[引用](verdict.md) する。
- 親・子・孫は、ノードどうしの相対的な関係を指す。
  - どの階層にも、同じ規則が当てはまる。

兄弟ノードの AND と OR の関係は、[真偽値の伝播](propagation.md) に書く。

## 仮説

- 仮説は、主文と背景情報からなる。
- 主文は 50 字以下にする。
  - 根拠：依頼者の要求。
- 背景情報には、文字数の上限を設けない。

文字数は、Unicode NFC（正規化形式の 1 つ）に正規化したあとのコードポイント数で数える。

- なぜ：実装の言語によらず、同じ数になるから。

## ストーリー

- ストーリーは、「子仮説がすべて真なら、親仮説は真になる」ことを保証する論理的なつながりである。
  - この保証は、兄弟ストーリーに頼らず、そのストーリーだけで成り立つ。
  - 兄弟ストーリーは、同じ親仮説を、別の論理で保証するものである。
  - なぜ：仮説の値は、子ストーリーの OR だから（[真偽値の伝播](propagation.md)）。
  - 親仮説の一部しか言えないストーリーが true になると、親仮説の残りを確かめないまま、親仮説が true になる。
- 親仮説を場合や側面に分けるときは、分けたものを兄弟ストーリーにしない。
  - 1 つのストーリーの子仮説として並べる。
  - 例：「試作セルは 25℃ と 45℃ で寿命の基準を満たす」では、25℃ のストーリーと 45℃ のストーリーを別々に立てない。
    - 1 つのストーリーの下に、25℃ の子仮説と 45℃ の子仮説を並べる。
- 親仮説の一部しか言えないストーリーがすでに反映されているときは、次のようにする。
  - そのストーリーを [inactive](inactive.md) にする。
  - 分けたものをすべて子仮説に並べた、新しいストーリーを立てる。
- ストーリーは、タイトルと概要からなる。
- タイトルは 50 字以下にする。
- 概要は 300 字以下にする。
  - 根拠：どちらも依頼者の要求。
- ストーリーは、1 つ以上の子仮説と一緒に作る。
- ストーリーを作ったあとは、子仮説の集合を変えない。
  - なぜ：ストーリーの論理は、その子仮説の組で審査されている。組を変えると、審査をやり直すことになる。
  - 組を変えたいときは、兄弟ストーリーを作る。

## 葉と検証結果

仮説は、次の 2 つを同時には持たない。

- 有効な検証結果
- active な子ストーリー

この 2 つについて、次のように呼ぶ。

- active な子ストーリーを持たない仮説を、葉と呼ぶ。
- 葉のうち、検証結果を持たないものを、未決の葉と呼ぶ。

値と、検証結果を持つ仮説の扱いは、次のとおり。

- 値を人やエージェントが入れられるのは、検証結果だけである。
  - ほかのノードの値は、すべて [伝播](propagation.md) で決まる。
- 検証結果を持つ仮説の下には、ストーリーを作れない。
  - なぜ：検証結果と子ストーリーの両方から値が決まると、どちらが正しいか定まらない。
  - 検証済みの葉を分解したいときは、親の階層に兄弟ストーリーを立てる。

検証結果の中身は、[検証結果と引用](verdict.md) に書く。

## 変更の経路

- 正式なデータを変えられるのは、承認された [apply request](../apply-request/README.md) の反映だけである。
  - なぜ：すべての変更を、審査と履歴の対象にするため。
- 例外は、利用者による repository の作成（根の主文の作成）だけである。
- apply request によらずに `main` が変えられても、Logiforge は受け入れる。そのときの扱いは、[main への直接の変更](../apply-request/README.md#main-への直接の変更) に書く。

## 対応しないこと

- repository を作れる利用者を制限すること
- repository の削除
- repository の名前の変更
