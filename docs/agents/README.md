# 役割とハーネスの機能

誰が何をするかを確かめるときに読む。
エージェントは判断だけを担い、機械的な処理はハーネスが担う。

## Builder

Builder は、木を作り、葉を検証するエージェントである。
[Apply Request](../apply-request/README.md) の opener を担う。

- 問いを、ストーリーと子仮説に分解する。
- 葉を検証する。
  - 検証の手段は、文献検索と、プログラムの実装と実行である。
  - レポートと artifact を作り、`verdict.submit` を出す。
- 要再検討の仮説に対して、[仮説が偽になったとき](../tree/falsification.md) の対応をする。
- 計算機の中で検証できない葉について、[PVR](../threads/README.md) を起票する。
- PVR への記入を、検証結果に変換する。
- 依頼のスレッドに応える。
- ストーリーの論理の欠陥に気づいたら、`story.inactivate` を提案する。

木を作る主体と、葉を検証する主体は、分けない。

- なぜ：同じ主体が両方を担っても、審査が別の主体で行われる限り、問題が生じないから。

## Reviewer

Reviewer は、AR を審査するエージェントである。
AR の reviewer を担う。

- 審査の観点は、[Reviewer の審査観点](../apply-request/review.md) に書く。
- Reviewer は、Builder とは別の主体として動かす。

## 利用者

利用者は、[WebUI](../webui/README.md) を使う人間である。
利用者ができることは、次の 4 つだけである。

- 根の仮説の主文を作る。
- [スレッド](../threads/README.md) で、自由記述の依頼を出す。
- PVR を読み、結果を記入する。
- ループを一時停止する。

PVR には、問いを持ち込んだ人とは別の利用者（実験の担当者など）も記入できる。

## ハーネスの機能

次の機能は、エージェントではなく、ハーネスが担う。

- validator：AR の提出時と適用時に、[不変条件](../tree/README.md) を確かめる。
- 伝播エンジン：[真偽値の伝播](../tree/propagation.md) の規則で、値と要再検討を計算する。
- AR エンジン：[Apply Request](../apply-request/README.md) の状態を管理し、操作をまとめて適用する。
- スケジューラ：イベントからタスクを作り、担当に割り当てる（[スケジューラ](scheduler.md)）。
- 通知：イベントを、エージェントと利用者に知らせる。
- 履歴：すべての変更を記録する（[全体構成](../architecture/README.md)）。

なぜ：判断を伴わない処理をエージェントから外すと、エージェントは判断だけに集中できるから。
