# 役割とハーネスの機能

誰が何をするかを確かめるときに読む。
エージェントは判断だけを担い、機械的な処理はハーネスが担う。

## Builder

Builder は、木を作り、葉を検証するエージェントである。[Apply Request](../apply-request/README.md) の opener を担う。

- 問いを、ストーリーと子仮説に分解する。
- 葉を検証する。
  - 文献検索や、プログラムの実装と実行で検証する。
  - レポートと artifact を作り、`verdict.submit` を出す。
- 偽が出たときや、要再検討のときに、代わりのストーリーを考える（[仮説が偽になったとき](../tree/falsification.md)）。
- 計算機の中で検証できない葉について、[PVR](../threads/README.md) を起票する。
- PVR への人の記入を、検証結果に変換する。
- 依頼のスレッドに応える。
- ストーリーの論理の欠陥に気づいたら、`story.inactivate` を提案する。

木を作る主体と、葉を検証する主体は、分けない。
- なぜ：同じ主体が両方を担っても、審査が別の主体で行われる限り、問題が生じないから。

## Reviewer

Reviewer は、AR を審査するエージェントである。AR の reviewer を担う。

- 審査の観点は、[Reviewer の審査観点](../apply-request/review.md) に書く。
- Reviewer は、Builder とは別の主体として動かす。

## owner

owner は、問いを持ち込む人間である。owner がするのは、次の 3 つだけである。

- 根の仮説の主文を書く。
- [スレッド](../threads/README.md) で、自由記述の依頼を出し、PVR に結果を記入する。
- ループを一時停止する。

## ハーネスの機能

次の機能は、エージェントではなく、ハーネスが担う。

- validator：AR の提出時と適用時に、不変条件を確かめる（[仮説とストーリーの木](../tree/README.md)）。
- 伝播エンジン：値と、要再検討の見え方を計算する（[真偽値の伝播](../tree/propagation.md)）。
- AR エンジン：AR の状態を管理し、操作をまとめて適用する（[Apply Request](../apply-request/README.md)）。
- スケジューラ：イベントからタスクを作り、担当に割り当てる。ループを止めるかどうかを判断する（[スケジューラ](scheduler.md)）。
- 通知：イベントを、エージェントと人間に知らせる。
- 履歴：すべての変更を記録する（[全体構成](../architecture/README.md)）。

なぜ：判断を伴わない処理をエージェントから外すと、エージェントは判断だけに集中できるから。
