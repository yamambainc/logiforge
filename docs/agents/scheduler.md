# スケジューラ

ループがどう回り、いつ止まるかを確かめるときに読む。
スケジューラは、エージェントではなくハーネスの機能である（[役割](README.md)）。

## タスク

スケジューラは、イベントからタスクを作る。

| イベント | タスク | 担当 |
|---|---|---|
| AR が open になった、または修正された | 審査 | Reviewer |
| AR に `request_changes` が付いた、または適用に失敗した | 修正 | opener |
| スレッドが開かれた、または返信が来た | 対応 | Builder |
| 未決の葉ができた | 検証または分解 | Builder |
| 仮説が要再検討になった | 代わりのストーリーの検討 | Builder |
| 引用元が変わった | 引用している検証結果の見直し | Builder |

- タスクの対象にするのは、active なノードだけである。
  - なぜ：inactive な部分木は、伝播に関与しないから（[inactive 化](../tree/inactive.md)）。
- 1 つのタスクは、1 つの担当にだけ割り当てる。
  - 担当が途中で止まったら、そのタスクを別の担当に回す。
- Builder は、タスクを次のどれかで終える。
  - AR を出す。
  - スレッドに書く。
  - 理由を残して閉じる。

イベントの詳細は、各ページに書く。

- 未決の葉：[葉と検証結果](../tree/README.md)
- 要再検討：[真偽値の伝播](../tree/propagation.md)
- 引用元の変化：[引用元が変わったとき](../tree/verdict.md)

## 根拠部分木

根拠部分木は、根の値が true か false のときに、その値を支えている部分木である。
根から、次の規則でたどる。

- true の仮説からは、true の子ストーリーへ進む。
- ストーリーからは、すべての子仮説へ進む。
- 葉で止まる。

## 停止条件

スケジューラは、次のどれかに当てはまったら、ループを止める。

- 根の値が true か false に決まり、根拠部分木の中に未処理のタスクがない。
  - なぜ：引用元が変わっても値は自動では変えないので、根拠部分木の見直しを終えるまでは結論を確定できないから。
- 予算を使い切った。
- owner が一時停止した。

実行できるタスクがない間は、新しいイベント（人の記入など）を待つ。
