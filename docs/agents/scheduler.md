# スケジューラ

ループがどう回り、いつ止まるかを確かめるときに読む。
スケジューラは、エージェントではなくハーネスの機能である（[役割](README.md)）。

## タスク

スケジューラは、次のイベントからタスクを作る。

| イベント | タスク | 担当 |
|---|---|---|
| AR が open になった | 審査 | Reviewer |
| AR が修正された | 審査 | Reviewer |
| AR に `request_changes` が付いた | 修正 | opener |
| AR の適用に失敗した | 修正 | opener |
| スレッドが開かれた | 対応 | Builder |
| スレッドに返信が来た | 対応 | Builder |
| 未決の葉ができた | 検証または分解 | Builder |
| 仮説が要再検討になった | 代わりのストーリーの検討 | Builder |
| 引用元が変化した | 引用している検証結果の見直し | Builder |

各イベントの定義は、次のページに書く。

- AR：[Apply Request](../apply-request/README.md)
- 未決の葉：[葉と検証結果](../tree/README.md)
- 要再検討：[真偽値の伝播](../tree/propagation.md)
- 引用元の変化：[検証結果と引用](../tree/verdict.md)

タスクの扱いは、次のとおり。

- タスクの対象にするのは、active なノードだけである。
  - なぜ：inactive な部分木は、伝播に関与しないから（[inactive 化](../tree/inactive.md)）。
- 1 つのタスクは、1 つの担当にだけ割り当てる。
- 担当が途中で止まったら、そのタスクを別の担当に回す。
- Builder は、タスクを次のどれかで終える。
  - AR を出す。
  - スレッドに書く。
  - 理由を残して閉じる。

## 停止条件

スケジューラは、次のどれかに当てはまったら、ループを止める。

- 根の値が決まり、根拠部分木の中に未処理のタスクがない。
  - 根の値が決まるとは、true か false になることをいう。
  - 根拠部分木は、[真偽値の伝播](../tree/propagation.md) に定義がある。
  - なぜ：引用元が変化しても値は自動では変えないので、根拠部分木の見直しを終えるまでは結論を確定できないから。
- 予算を使い切った。
- 利用者が一時停止した。

実行できるタスクがない間は、新しいイベントを待つ。
