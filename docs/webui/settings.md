# 設定

利用者が、repository を足し、GitForge とのつなぎ方を変える画面。
利用者だけが開ける。利用者でない人には、メニューに出さない。
利用者の決まりは、[役割](../roles/README.md#利用者) に書く。

## ワイヤフレーム

```
+---------------------------------------------------------------+
| 設定    [repository] [GitForge] [記録の鍵]                    |
+---------------------------------------------------------------+
| repository                                         [足す]     |
| question-a   my-org/question-a                     [外す]     |
| question-b   my-org/app : logiforge/question-b                |
|                               [最初の問いを入れる] [外す]     |
+---------------------------------------------------------------+
| 最後に変えた人：alice  2026-11-18 12:00                       |
+---------------------------------------------------------------+
```

「足す」を押すと、タブの中で、2 つの段を順に進める。

```
+---------------------------------------------------------------+
| (1. repository) (2. 最初の問い)                               |
| question-c の根に置く、最初の問い（根の仮説）を書きます。     |
| 根の仮説の主文  [                                    ] 0 / 50 |
| 背景情報        [                                    ]        |
| [用意する] [あとで入れる]                                     |
+---------------------------------------------------------------+
```

## タブ

| タブ | 変えられるもの |
|---|---|
| repository | GitHub を使う構成の repository と、ディレクトリの repository の一覧 |
| GitForge | GitHub App か Forgejo のつなぎ方。秘密の入れ直し。見回りの間隔 |
| 記録の鍵 | 記録の署名の鍵の一覧。新しい鍵を作る |

- 変えた設定は、サーバを起動し直さずに効く。
  - worker が読む設定（repository の一覧、見回りの間隔）は、worker が次に一覧を読み直したときに効く。画面に、そのことを示す。
- どのタブにも、最後に変えた利用者と時刻を示す。

## repository を足す

repository は、この画面だけで足す。
新しい repository も、すでにスナップショットツリーのある git リポジトリも、同じ段で足す。

1. repository：名前と、どの git リポジトリを使うかを入れる。
2. 最初の問い：根の仮説の主文と、背景情報（なくてもよい）を入れて、repository を用意する。

- 段を進めるあいだ、ほかの画面には移らない。
- 終わったら、用意したことと、スナップショットツリーを開くボタンを示す。

### 1. repository

- GitHub を使う構成では、名前と `owner/name` を入れて登録する。
  - GitHub App が install されていない owner なら、install の画面へのリンクを示す。
- Forgejo を使う構成では、次のどちらかを選ぶ。
  - Forgejo に新しく作る：名前だけを入れる。登録はしない。2 で、Forgejo に repository を作る。
  - git リポジトリの中のディレクトリを使う：下のディレクトリの repository と同じ。
- ディレクトリの repository では、名前と、git リポジトリと、ディレクトリのパスを入れて登録する（[導入](../adoption/README.md)）。

### 2. 最初の問い

- 登録した git リポジトリ（ディレクトリの repository ならディレクトリ）にスナップショットツリーがもうあれば、この段を飛ばし、「もうある」と示す。
  - 例：外した repository を登録し直したとき。
- この段を閉じても、一覧の「最初の問いを入れる」から続けられる。
  - 一覧は、スナップショットツリーがまだない repository にだけ、このボタンを示す。
  - Forgejo に新しく作るときは、まだ何も登録していないので、一覧に出ない。もう一度「足す」から始める。
- 主文の決まりは、[仮説](../tree/README.md) に従う。

## 外すときの確かめ

- repository を外すときは、「スナップショットツリーは読めなくなります。git リポジトリは消えません」と示し、確かめてから外す。

## 秘密

- 秘密は、画面に示さない。入れ直すことだけができる。
- 秘密ごとに、「設定済み」と、最後に変えた人と日時を示す。
- 入れ直せる秘密は、GitHub App の client secret と秘密鍵（`.pem`）、Forgejo の client secret と worker のトークンである。
  - 秘密鍵は、ファイルを選んで入れる。
- 入れ直した秘密は、サーバを起動し直さずに効く。
- 入れ直す手順を、画面に示す。
  1. GitForge の画面で、新しいものを作る。
  2. この画面に入れる。
  3. GitForge の画面で、古いものを消す。
