# セットアップ

管理者が、Logiforge を初めて動かしたときに、GitForge とのつなぎ方と最初の管理者を決める画面。
セットアップが終わるまで、WebUI はこの画面だけを示す。

- セットアップの画面は、サーバのログに出るコードを入れた人だけが使える。
  - なぜ：最初の管理者が決まる前に、サーバを動かす人のほかの人に、設定を取られないようにするため。
- セットアップが終わったら、この画面は使えなくなる。

## ワイヤフレーム

```
+---------------------------------------------------------------+
| Logiforge のセットアップ                                      |
+---------------------------------------------------------------+
| 1. コード      [ サーバのログのコード          ] [次へ]       |
| 2. 構成        (o) GitHub   ( ) Forgejo                       |
| 3. GitHub App  owner [ my-org        ]  WebUI [ https://... ] |
|                [x] ほかの owner にも install する              |
|                [GitHub で App を作る]                          |
| 4. install     [GitHub で install する]                        |
| 5. サインイン  [GitHub でサインインして、管理者になる]         |
+---------------------------------------------------------------+
```

Forgejo を選んだときは、3 と 4 のかわりに、次の段を示す。

```
+---------------------------------------------------------------+
| 3. Forgejo     URL [ https://forgejo.example ]                |
|                ブラウザからの URL [                ]          |
|                organization [ my-org ]                        |
| 4. サインイン  redirect_uri: https://.../oauth/callback       |
|                client_id [      ]  client secret [      ]     |
|                worker  [ user ]  トークン [      ]  [確かめる]|
| 5. サインイン  [Forgejo でサインインして、管理者になる]        |
+---------------------------------------------------------------+
```

## 段

- 段は、上から順に進める。前の段が終わるまで、次の段は押せない。
- コードは、サーバのログに出ているものを入れる。
  - 合わなければ、「コードが違います。サーバのログの、いちばん新しいコードを入れてください」と示す。
- 途中でページを閉じても、入れた設定は残る。コードを入れ直せば、続きから進む。
- 最後の段でサインインした人が、最初の管理者になる。
  - 終わったら、[設定の画面](settings.md) を開き、repository を登録するように示す。

## 秘密の扱い

- client secret とトークンの入力欄は、入力の文字を隠す。
- 置いた秘密は、画面に戻さない。「置きました」とだけ示す。
