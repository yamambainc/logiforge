## 互換のない変更

設定の置き方と、GitHub とのつなぎ方を変えた。v0.3.0 からの移行には対応しない。新しく入れ直す。

- 設定は、設定の DB（SQLite）に置く。起動時に渡すのは、設定の DB の場所と 2 つの鍵と、ホストに結び付くものだけである（[環境変数](https://github.com/yamambainc/logiforge/blob/v0.4.0/design/deploy/env.md)）。
  - 渡すもの：`LOGIFORGE_DB`、`LOGIFORGE_BACKEND_KEY`（バックエンドだけ）、`LOGIFORGE_SHARED_KEY`（両方）、`LOGIFORGE_ADDR`、`LOGIFORGE_STORE_DIR`、`LOGIFORGE_WORKER_DIR`、`LOGIFORGE_GIT_CACHE_DIR`、`LOGIFORGE_GIT_ALLOW_PROTOCOL`。鍵は `_FILE` でも渡せる。
  - なくしたもの：`LOGIFORGE_GITFORGE`、`LOGIFORGE_GITHUB_*`、`LOGIFORGE_FORGEJO_*`、`LOGIFORGE_OAUTH_*`、`LOGIFORGE_USER_*`、`LOGIFORGE_RECORD_KEYS`、`LOGIFORGE_RECORD_PUBLIC_KEYS`、見回りの間隔などの環境変数。
  - 秘密（GitHub App の秘密鍵と client secret、Forgejo の client secret と worker のトークン、記録の署名の鍵）は、設定の DB に暗号化して置く。worker は、バックエンドの鍵を持たず、設定の DB を読むだけである（[秘密の暗号化](https://github.com/yamambainc/logiforge/blob/v0.4.0/design/settings/secrets.md)）。
- GitHub を使う構成では、GitHub App を 1 つだけ使う。読むことと、WebUI のサインインの両方を担う（[GitHub App とトークン](https://github.com/yamambainc/logiforge/blob/v0.4.0/design/adapters/github-app.md)）。
  - OAuth App と、読むだけの GitHub App は使わない。
  - App の秘密鍵は、バックエンドだけが持つ。worker は、バックエンドが Read に絞って作った installation token を、設定の DB から読む。
  - CLI（opener と reviewer）は、これまでどおり `gh auth login` のトークンを使う。
- 利用者（`user`）の名簿をなくした。利用者は、登録した repository に Write 以上がある人（GitHub）か、organization の、コードに書ける team にいる人（Forgejo）で、WebUI でサインインした人である（[利用者](https://github.com/yamambainc/logiforge/blob/v0.4.0/design/settings/users.md)）。
  - 権限は 60 秒だけ覚える。設定を変える要求では、覚えたものを使わない。
  - Forgejo の利用者の team は、コード、issue、pull request に書ける team にする。
- 設定は、WebUI の画面で変える。サーバを起動し直さずに効く。

### 入れ方

1. v0.4.0 のバイナリかイメージで、新しい設定の DB と空の置き場で起動する。2 つの鍵（32 バイトの乱数の base64）を作って渡す。
   - systemd で置くときは、ユニットの見本（`deploy/systemd/`）を入れ直す（[1 台の Linux に置く](https://github.com/yamambainc/logiforge/blob/v0.4.0/docs/adoption/linux-host/README.md)）。
2. WebUI の `/setup` を開く（[セットアップ](https://github.com/yamambainc/logiforge/blob/v0.4.0/docs/webui/setup.md)）。
3. GitHub を使う構成では、画面から GitHub App を作り、repository の owner に install し、最初の repository を登録して、サインインする。Forgejo を使う構成では、OAuth2 のアプリケーションと worker のユーザーとトークンを入れて、サインインする。
4. 前の版の OAuth App、読むだけの GitHub App、personal access token は、GitHub と Forgejo で消す。

## 新しいこと

- 初回のセットアップの画面（[セットアップ](https://github.com/yamambainc/logiforge/blob/v0.4.0/docs/webui/setup.md)）。
  - だれでも、最初の段から進められる。最後の段でサインインした人が、最初の利用者になる。セットアップが終わったら、この画面は使えない。
  - ほかの人に先にセットアップされたら、設定の DB を消して、起動し直す。セットアップの前のサーバには、データがないからである（[初回のセットアップ](https://github.com/yamambainc/logiforge/blob/v0.4.0/design/settings/setup.md)）。
  - GitHub App は、manifest flow で画面から作る。Webhook は使わない。
- 設定の画面（[設定](https://github.com/yamambainc/logiforge/blob/v0.4.0/docs/webui/settings.md)）。repository の登録と外す、GitForge とのつなぎ方、秘密の入れ直し、見回りの間隔、記録の署名の鍵。
  - 登録できるのは、自分が Write を持つ git リポジトリだけである。
  - 自分が利用者でなくなる変更（最後の repository を外す、間違った client secret を置くなど）は、受け付けない。
- WebUI からのレビュー（[apply request と履歴](https://github.com/yamambainc/logiforge/blob/v0.4.0/docs/webui/history.md)）。利用者は、apply request の画面で、approve、request_changes、comment ができる。approve で反映の条件を満たせば、本人のトークンで反映する。
- `logiforge settings load` と `logiforge settings rekey`（[設定のコマンド](https://github.com/yamambainc/logiforge/blob/v0.4.0/design/settings/README.md#設定のコマンド)）。
