## 互換のない変更

GitHub を使う構成（`LOGIFORGE_GITFORGE=github`）で、personal access token を使わなくなった。Forgejo を使う構成は変わらない。

- worker とバックエンドが repository を読むトークンを、`LOGIFORGE_GITHUB_READ_TOKEN`（fine-grained personal access token）から、読むだけの GitHub App の installation token に変えた。
  - `LOGIFORGE_GITHUB_APP_ID` と `LOGIFORGE_GITHUB_APP_PRIVATE_KEY`（`_FILE` でもよい）を渡す。installation token は、Logiforge が作り、切れる前に作り直す。
  - `LOGIFORGE_GITHUB_READ_TOKEN` を置いたままだと、worker もバックエンドも起動しない。
  - App は読むだけで、書かない。反映かの判定は、これまでどおり中身だけで決める。
  - public のリポジトリだけなら、App なしで（トークンなしで）動くのは、これまでどおりである。
  - `LOGIFORGE_GIT_TIMEOUT` は `20m` より短くする。長いと、worker が起動しない（installation token が git の操作のあいだに切れないように）。
- opener と reviewer（人とエージェント）のトークンは、`gh auth login`（OAuth）で得たものにする。personal access token の案内はなくした。

### 上げ方（互換のない変更）

1. 読むだけの GitHub App を作り、Logiforge の repository に install する（[Logiforge の repository を GitHub に置く](https://github.com/yamambainc/logiforge/blob/v0.3.0/docs/adoption/github.md#読むだけの-github-app)）。
2. 設定から `LOGIFORGE_GITHUB_READ_TOKEN` を消し、`LOGIFORGE_GITHUB_APP_ID` と `LOGIFORGE_GITHUB_APP_PRIVATE_KEY_FILE` を足す。systemd で置いたときは、ユニットの見本（`deploy/systemd/`）を入れ直し、秘密鍵を `/etc/logiforge/secrets/github_app_key.pem` に置く。
3. worker とバックエンドを起動し直す。repository も記録も、作り直さなくてよい。
4. 前の personal access token は、GitHub で取り消す。エージェントが personal access token を使っていたら、`gh auth login` で得たトークンに替え、古いものを取り消す。

## 新しいこと

- 1 台の Linux に systemd で置き、Tailscale で公開する手順と、ユニットの見本（`deploy/systemd/`）。worker のハートビートを見るタイマー（`logiforge worker-health`）も入る。バックアップは、置き場の `keep/` を写して取る（[1 台の Linux に置く](https://github.com/yamambainc/logiforge/blob/v0.3.0/docs/adoption/linux-host/README.md)）。
- 読むだけの GitHub App の installation token は、登録したリポジトリと読む権限だけに絞って作り、1 時間で切れる前に作り直す（[GitHub アダプタ](https://github.com/yamambainc/logiforge/blob/v0.3.0/design/adapters/github.md#読むだけの-github-app)）。
